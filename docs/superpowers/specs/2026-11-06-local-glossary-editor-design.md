# N2a：本地人物／术语资料编辑与预览

日期：2026-11-06。基线：`cb71d2f228e847900769f93f05edc05e2f285b47`。

状态：用户已逐节确认设计，书面规格待独立审阅与用户最终审阅；未开始实现。

## 1. 目标与权威边界

在现有 Web 工作台中完整编辑第二版人物／术语资料，将其保存为独立、未批准的本地草稿，支持重启继续编辑、资料卡展示及目标块可见性判定。采用独立应用层模块和布局 A（列表＋编辑区，预览独立切换）。

沿用 [N0 第 23 节](../../novel-workbench-n0.md#23-上下文格式第二版格式与兼容底座设计)的资料字段及 [第 24 节](../../novel-workbench-n0.md#24-n2a-首批范围与可见性判定设计)的完整校验、整卡门槛、条件称呼与身份报告。本文只放开本地编辑／预览，不放开批准与外发。

- 本文独立文件是**编辑器工作状态**，不是第二种生产资料来源。第 23.1 节的生产第二版仍是原位置的 `glossary.json`，不新增 `entities.json` 等生产输入。
- 不改现有 `glossary.json`、上下文草稿／快照、版本清单、批准事件、译稿、导出、勘校、札记和模型消费路径。独立草稿不会使旧上下文失效，也不影响其原有生产结果。
- 第二版生产入口继续拒绝并提示“人物／术语资料尚未开放”。批准现有第一版上下文不等于批准编辑器草稿；页面明确说明二者互不包含。
- `tentative`／`confirmed` 是资料记录状态，不是批准状态；“已保存”“校验通过”“自动候选”均不授予批准、外发或定稿资格。
- 不自动导入、转换、升级旧数组，不执行旧自由文本 scope。不提供批准、送审、未来资料绕过开关、模型调用、提示词拼装或外发接口。

## 2. 模块与接口职责

### 2.1 应用层

在 `ziyuan-app::translation` 下增加独立资料草稿模块；复用 `glossary.rs` 的字段模型及严格校验、`visibility.rs` 的 `evaluate_context_visibility`、现有项目读取和受管文件写入原语。不把资料功能继续塞入人工译稿的 `draft.rs`，不复制批准／恢复协议。

公开能力按以下职责分开，具体 Rust 标识符由实施计划固定：

| 能力 | 输入 | 输出及副作用 |
| --- | --- | --- |
| 读取编辑视图 | 项目 ID | 当前项目摘要、章段／块选择数据、可选服务器草稿；不创建草稿 |
| 保存草稿 | 项目 ID、请求 ID、预期修订、完整资料 | 保存回执；只发布独立草稿状态 |
| 校验当前输入 | 项目 ID、完整资料 | 输入摘要、当前项目摘要、有效性及字段问题；不保存 |
| 目标块预览 | 项目 ID、完整资料、目标块 ID、本次关联 | 输入绑定摘要及既有身份报告；不保存 |

保存不以第二版语义校验成功为前提；校验和预览必须重新读取并核对当前项目，不能信任浏览器提供的项目正文、顺序或散列。保存使用当前项目验证项目身份及写权限协议，不把其章段绑定冻结为批准依据。

### 2.2 Web

增加小型资料 API 适配模块和独立前端模块，沿用现有路由、静态资源、中文错误与认证模式。不引入新前端框架，不重构无关工作台。

计划接口为：

- `GET /api/text/{project}/materials`：编辑视图和服务器草稿。
- `POST /api/text/{project}/materials/draft`：显式保存完整草稿。
- `POST /api/text/{project}/materials/validate`：校验当前输入。
- `POST /api/text/{project}/materials/preview`：当前输入的本地可见性预览。

认证缺失返回 401。观政身份可 GET，并仅对上述两个**无写入**的校验／预览 POST 增加精确匹配例外，沿用已有参考预览例外模式；保存仍为 403，不使用前缀通配放行。写接口继承现有同站认证及请求保护，不接受令牌或资料内容进入 URL、日志或错误追踪。

草稿修订／请求 ID 冲突返回 409；请求超限为 413；格式／项目／块／关联错误及无效预览为现有材料错误类别，附可展示的中文问题。读取损坏、新版本或 I/O 失败不得包装为“空草稿”。

## 3. 未完成资料与校验分层

### 3.1 编辑状态

草稿的 `material` 使用现有 `StructuredGlossary` 的字段和类型，固定 `format: 2`，不新增生产字段。所有现有可选字段、数组顺序、相同姓名的不同 ID 都须保留。

“未完成”表示字段类型正确，但可以违反现有资料语义：如空姓名／ID、空 allowed、重复或失效引用、错误范围、找不到的章段、证据短引不匹配。新条目使用该类型可表达的空字符串／空数组；未选择必填位置时用空章 ID，未指定可选位置时为缺省。枚举使用明确合法默认值并展示给用户，不用未知枚举或额外半成品格式。

未知字段、重复 JSON 键、错误类型、不支持的 `format`、非法枚举及过大请求不属于可保存的未完成资料。Rust 直接构造的输入也须做同样的保存边界检查，不能只靠 Web 反序列化。

### 3.2 三种独立状态

1. 保存边界：类型、格式、深度、数组／文本资源上限满足，才能落盘；允许语义未完成。
2. 第二版校验：复用严格解析、引用和项目验证；只有完整资料全部通过才可运行可见性判定，不跳过坏条目。
3. 可见性判定：只对有效资料、真实目标块和有效本次关联运行既有纯函数；其结果仍非生产材料。

校验返回可定位字段路径、稳定问题类别与中文说明。可以先报告首个确定错误，修正后重验，不承诺一次穷尽所有错误；不得自行重写资料以“通过”校验。保存回执不附带自动晋升的“有效”状态，页面独立显示校验状态。

保存硬上限沿用现有资料长度／数组最大值，但允许空值及语义错误；资料 JSON 的紧凑 UTF-8 序列化至多 1 MiB。保存请求及校验／预览请求体至多 2 MiB，含关联；完整持久化信封至多 8 MiB。三者分别检查，单数组上限不意味着所有数组上限的笛卡尔积都能保存。禁止深度异常、控制字符及超长字段进入服务器工作状态；被拒输入仍留在页面并允许复制恢复内容。

实现应小范围复用／拆分当前格式检查的资源边界与语义检查，而不是维护另一套不同的生产校验规则。浏览器即时提示是辅助，服务端为最终依据。

## 4. 独立持久化与并发协议

### 4.1 路径及内容

文件固定为 `.ziyuan/text-projects/<project>/material-draft.json`，不在 `context/`、快照或导出目录中。只在显式保存时初始化。使用 `JsonFile` 的版本化信封，编辑器存储 schema 从 1 开始；它与内层 `format: 2` 是不同版本。

信封 data 包含项目 ID、不可预测的草稿修订身份、完整 `material`、请求回执表。修订身份每次新保存随机生成，避免内容改回原样时出现 ABA；`JsonFile.revision` 仍是底层发布计数，不当作批准事件。

请求回执表按请求 ID 保存请求摘要及原回执（草稿修订、资料内容摘要）。摘要覆盖项目、预期修订和完整资料，采用固定字段顺序的规范序列化，不能依赖任意 JSON 对象键顺序。回执与正文在同一文件原子发布，不引入多文件事务、事件、批准记录或后台恢复任务。

已有文件读取时核对存储版本、项目身份、修订形状、保存边界及回执结构；语义错误属于可恢复编辑内容，不属于文件损坏。更高存储版本提示升级。损坏、过大及路径异常返回明确错误，不重置或覆盖。

### 4.2 保存步骤

1. 验证请求形状、资源上限及请求 ID（沿用现有人工稿请求 ID 规则）；确认项目身份。
2. 取得现有工作区写锁，核对 `ensure_writable`，再取得资料文件锁；锁序固定为工作区→资料文件，不与项目锁反向嵌套。
3. 在锁内重新读取当前文件并核对身份和路径，不使用锁外的旧内容决定写入。
4. 已有同请求 ID 且摘要相同：返回原回执，不再写盘；摘要不同：409。旧请求即使在后来保存之后重试，也只能返回历史回执，绝不回滚正文。
5. 新请求的 `expected_revision` 必须等于当前草稿修订；文件不存在时只接受 `null`。不符返回当前修订，不覆盖。
6. 生成新修订及回执，预先核对整个信封大小，使用同目录临时文件、刷盘和原子替换发布。只在发布成功后返回成功。

回执不静默淘汰，以保持跨重启重试语义；完整状态超过 8 MiB 时明确拒绝新保存，旧文件和当前输入保留。不新增清理／压缩协议。测试必须覆盖接近上限及回执导致超限的情形，界面说明容量问题而非无限重试。

锁超时、磁盘错误、序列化失败及替换前中断保留旧发布；替换后响应丢失可用同请求重试确认。沿用存储原语的真实持久性边界，不承诺额外断电保证。

### 4.3 只读行为及路径

读取／校验／预览不得初始化草稿、目录、工作区写协议或草稿锁文件。`JsonFile::load` 会创建锁文件，不能不加区分地用于新只读入口：对原子发布的资料文件采用限长、单文件句柄读取和同一信封解码；读到的是旧或新完整发布，不据其结果写入。

项目与草稿路径沿用现有身份、普通目录／文件和符号链接检查；不接受客户端路径。写入前检查目标、父目录与锁文件，拒绝路径穿越及符号链接。项目读取沿用现有已核验读取入口；继承既有项目读取可能使用现存锁的约定，不将其误称为整个工作区绝无底层锁活动。资料读取及纯预览本身不创建新资料状态。

## 5. 预览数据流与有效期

编辑视图提供当前项目章段及块的真实顺序、原文显示和摘要。服务端项目摘要采用现有模式：已核验 `Project` 的确定序列化 SHA-256，包含章段正文、顺序和块结构；不接受客户端自报摘要。

- **资料卡**在浏览器按当前表单生成，可以显示本地姓名、译法、别名、声音与证据正文，并固定注明“编辑者视图，不代表目标块可见”。语义无效时保留展示并标错。
- **校验**发送当前完整资料，返回资料摘要、项目摘要及问题；不写服务器草稿。
- **范围预览**发送当前完整资料、目标块 ID 与临时 `ParagraphAssociations`。本次关联在页面内手填，区分未标注、明确未知、叙述和具体人物；不通过姓名／原文推断。刷新后不保留，不写会话恢复副本、服务器文件或生产材料。
- 预览先完整校验资料、项目、目标块与关联，再调用既有判定函数。不另造第二套筛选，不将 filtered ID 重新拼装成“安全提示词”。
- 结果只含既有身份报告，以及资料／项目／目标块／关联的绑定摘要。保留 `applicable` 与 `automatic` 两层语义、原状态、段号及诊断；规则按“所属人物 ID＋当前数组下标”定位，不承诺跨编辑稳定身份。

页面为每次校验／预览保存输入快照和本地请求代次。任何资料、块、关联变化立即使旧结果过期；返回时核对代次及输入，晚到响应不能覆盖当前页面。

页面进入、重新聚焦和手动运行时重新读取项目摘要；发现项目变化立即使旧结果过期。请求处理前后重核当前项目摘要，变化则返回项目已变而不是发布旧报告。页面显示“基于项目摘要……的本次结果”，不承诺无需刷新即可感知任意外部进程瞬时改盘，也不声称报告对未来保持有效。

服务器保存回执也必须核对当前页面项目、待保存请求 ID 和输入快照；保存期间继续编辑时，只确认提交的快照已保存，后续输入仍显示未保存。历史回执不把页面修订退回旧值，需重新读取服务器视图并保留当前输入。

## 6. Web 布局 A 与交互

入口位于现有项目工作台，命名“本地资料”，不叫批准上下文。顶部固定展示“未批准草稿；批准、模型调用与外发关闭”，并分别展示服务器保存状态、会话恢复状态和校验状态。

左侧按人物／术语列出姓名或 source＋ID；同名不合并，空值显示“未命名”。使用独立的页面条目键追踪选择和错误定位，不能用可能重复／改动的资料 ID 作 DOM 身份。右侧为“编辑／资料卡／范围预览”标签；窄屏收起列表并单列展示。

- 完整编辑现有 Term、Person、PersonVoice、AddressRule、scope、available_from 和 evidence 字段，不新增格式语义。
- 类型化选择器显示 ID 与标签；失效引用保留为“已失效：原 ID”，可修复或删除，不静默丢弃。ID 可直接编辑，不自动级联改写引用；清楚提示可能出现引用错误。
- 条目、规则、证据及例句可以增删；保留数组顺序，不提供额外拖拽排序功能。删除均确认，人物／术语被引用时列出影响，不级联删除或自动替换。
- 字段错误可跳转定位；切换记录／标签、验证失败、请求失败不重建或清空当前输入。中文输入组合期间不触发会破坏光标或未提交文本的重新渲染。
- 显式“保存草稿”不触发校验晋升或批准；没有草稿时展示空编辑状态而不写盘。已存在但损坏的草稿显示错误，不能用空白覆盖。
- 观政身份可查看资料卡及运行只读校验／预览，不能改服务器草稿。界面禁用编辑／保存，服务端仍独立拒绝写入。
- 所有姓名、证据、备注、错误与 ID 使用文本节点或正确转义输出，绝不将资料作为 HTML 执行；不自动访问证据或文本中的 URL。

### 6.1 会话恢复与冲突

沿用现有人工编辑器的状态机思路而非照搬批准状态。浏览器会话恢复副本按同源工作区、项目和模块命名，包含表单资料、服务器基线修订及待保存请求快照；不包含令牌、临时关联、报告或批准资格。只使用会话存储，不承诺浏览器关闭、换设备后的恢复。

会话写入失败／配额不足显示警告，表单仍留内存，可复制完整可恢复内容；不能显示“已保存”。输入超出服务器边界也不截断，尽力保留并允许复制。

首次加载若会话副本与服务器不同，展示两者身份，由用户选择恢复待保存输入或加载服务器版本。恢复副本不自动把旧基线改成当前修订以绕过冲突；发生冲突时保留本地内容，提供重新加载（确认放弃本地输入）及复制恢复内容，不自动合并。

刷新／离页前保存会话副本并提示未保存；点击其他条目或标签不丢失整份表单。保存成功只清除对应快照的暂存，后续新输入继续暂存。会话恢复内容仅是用户恢复材料，不新增服务端导入接口或生产导出。

## 7. 验收矩阵

实现采用先失败后通过的测试，预期来自既有 N0 固定样本和当前兼容基线，不能从新实现输出反推。

| 范围 | 必验情形 |
| --- | --- |
| 字段往返 | 全部第二版字段、可选缺省、空数组、同名不同 ID、重复／失效 ID、修改 ID 不级联、条目顺序；不得删字段或静默修复 |
| 未完成保存 | 空必填、空 allowed、悬空引用、错误范围／证据保存后新进程读取；严格校验失败，报告不生成，资料卡仍可看 |
| 资源边界 | 请求体／资料／信封各上限等于值与紧邻超限；多字节 UTF-8、单项最大长度、各数组最大条数、极深输入及重复 JSON 键 |
| 并发重试 | 首次创建竞争、相同请求重试、ID 异体请求、跨重启重试、旧请求在新保存后重试、A→B→A 修订、两个页面旧修订拒绝 |
| 原子与损坏 | 临时文件创建／写入／替换失败、替换前后进程中断、响应丢失；旧或新完整发布，不出现假保存；损坏、版本过高、容量耗尽不覆盖 |
| 路径与只读 | 不存在／非法项目、路径穿越、父目录／目标／锁为符号链接；GET／校验／预览不创建资料状态；未认证拒绝、观政保存拒绝且盘面不变 |
| 可见性 | 直接执行 N0 固定样本及既有独立测试；整卡、未来依赖、块首／块中揭示、章序不同于 ID、条件术语、未知与未标注、诊断聚合、旧自由文本不执行 |
| 预览有效期 | 修改资料／项目／块／关联后失效，延迟旧响应、连续预览、校验失败、关联非法不展示旧成功；两层结果不混淆 |
| 页面保存状态 | 保存中继续编辑、重复点击／重试、历史回执、切换项目、延迟响应、409／网络失败；只确认实际保存快照，不丢新输入 |
| 会话恢复 | 刷新恢复、不同服务器基线、损坏副本、配额失败、未保存超限输入、重新加载确认；不持久化临时关联 |
| UI 实操 | 完整增改删、字段跳转、键盘、长证据／多规则、桌面／窄屏、同名选择、失效引用、中文组合输入；资料文本不执行脚本 |
| 生产隔离 | 第一版逐字节兼容和所有第二版生产拒绝继续通过；保存与预览不改变上下文、事件、导出／勘校；请求监测无编辑器引发的模型调用 |

性能测试从新进程和新页面走真实入口，覆盖首次加载与接近 1 MiB 的可保存资料、单数组上限以及接近 2 MiB 的关联请求；不只测平均小样。用按需展开／分页控制 DOM 和选择器，不一次渲染所有嵌套规则。记录加载、保存、校验、预览和表单交互实测；不自行降低第二版准确性或隐藏错误以换速度。本文不预设未经实测的响应时间承诺。

验证包括相关 Rust／Node 测试、全仓回归、fmt、Windows clippy、Linux GNU／macOS ARM64 交叉 clippy、文档链接与旧 CLI 兼容脚本。原生 CI 及真机测试另列，交叉检查不冒充原生测试；真实 IME 或断电等未完成项如实记录。没有模型请求材料组装入口，不能把“未发请求”冒充完整防剧透请求验收。

## 8. 交付顺序与明确不做

书面规格独立审阅并由用户最终认可后，才生成实施计划；计划按应用层草稿／校验、只读预览 API、Web 表单与恢复、端到端兼容验证的依赖顺序展开，不能趁本批开启生产批准。只做服务本功能的局部拆分，不顺带重构其他系统。

不做 CLI／TUI、N2b 段旁辅助、自动认人、字面出现索引、自动替换、持久化段落关联、旧资料导入转换、资料批准／送审、模型或网络调用、实际外发、预算截断、通用知识库、schema 外扩、包版本升级或发版。

实现完成后仍遵守 work 分支先验证、同提交六项 CI 全过后才考虑快进 main 的既有流程；任何推送、合并和发版均需后续明确授权。本设计文档提交不移动 main／work 书签，不代表完整 N2a 已交付。
