# 1.1.0 Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付本地文本整理与检查、syosetu 本地更新提醒，并让用户文档更容易理解。

**Architecture:** 两条功能线在 ziyuan-app 独立实现，共用 ziyuan-storage 的安全 JSON 保存机制。CLI/Web 只接入服务，不修改现有事件簿格式；文本工具不依赖联网和模型，关注检查不触发翻译。

**Tech Stack:** Rust 1.89、serde/serde_json、ring SHA-256、ureq 3、Tokio、axum、内嵌 HTML，jj colocated Git。

**设计依据：** `docs/superpowers/specs/2026-10-30-v1.1.0-design.md`。所有命令在仓库根目录执行；PowerShell 每条 cargo 命令检查 `$LASTEXITCODE`。执行前重新读取 AGENTS.md/CLAUDE.md 和当前文件，不覆盖已有工作。未勾选步骤均未实现。

## Chunk 1：共用保存机制与文本工具

### Task 1：安全保存独立 JSON 状态

**Files:** 新增 storage `json_file.rs`，修改 storage `lib.rs` 导出。锁和文件行为参考现有 EventLog，但不借用朝廷执行者锁。

- [ ] 写单测：首次保存、重开、损坏 JSON、未知版本、超限、同时写入、替换失败保留旧内容；锁文件固定，不跟着状态文件替换。
- [ ] 执行 `cargo test -p ziyuan-storage json_file -- --nocapture`，确认新测试因缺失实现失败。
- [ ] 实现 `JsonFile<T>` 的有锁读取／修改接口；锁内重读，不暴露解锁后保存过期快照的接口。使用 Rust 1.89 安全文件锁，无 unsafe。
- [ ] 读取和写入采用相同大小上限；序列化后、替换前检查字节数，超限拒绝且保留旧状态。测试恰好上限、上限加一字节，以及失败后能重新打开旧文件；提醒积累也不得写出自身无法读取的状态。
- [ ] 保存到同目录唯一临时文件，flush/sync 后替换。Windows 已存在文件的替换必须证明不先删原文件；若 std 不足以安全实现，停止并提交可选方案，不能静默降级。
- [ ] 状态增加整数修订号和 schema_version；未知版本拒绝，损坏不初始化为空。测试故障发生在写临时文件、替换前后和锁竞争时旧／新文件只能完整出现。
- [ ] 重跑上述测试和 `cargo clippy -p ziyuan-storage --all-targets -- -D warnings`。
- [ ] 更新 CHANGELOG Unreleased，提交 `存储：新增带锁的独立 JSON 状态保存`。

### Task 2：文本项目与稳定段落编号

**Files:** 新建 app `text_project` 模块与 app/tests/text_project.rs；修改 app/lib.rs。

- [ ] 测试日英不对称样本、相同段落重复、LF/CRLF、多空行、Unicode、空输入和非法 UTF-8；明确“同版本重复分块编号不变”。
- [ ] 执行 `cargo test -p ziyuan-app --test text_project`，确认缺失接口导致失败。
- [ ] 定义项目格式：`schema_version, id, title, source_language, target_language, provenance, chapters`。来源信息为用户声明；ID 与目录名由程序生成，不使用作品标题拼路径。
- [ ] 实现原件复制和 SHA-256；导入顺序由输入列表决定。导入前后核对原文件身份与内容，拒绝文件夹、越界／符号链接目标；不修改原件。
- [ ] 实现自然段识别和空行布局保存；每段 ID 由章节次序和段落次序确定，记录源字节对应范围。同一源版本 ID 不受块大小影响。
- [ ] 分块计算最终提示文件字节数，默认上限 48 KiB；大于上限的单段报章节和位置，不截断。测试 1 字节边界和编号开销。
- [ ] 用暂存目录构建整个项目，成功后一次公布；失败清理仅本次创建的暂存文件，不动用户文件。同 ID 并发导入不得覆盖。
- [ ] 重跑文本测试，确认导入结果重开一致、失败没有可见半项目。
- [ ] 提交 `文本：新增本地项目与按自然段分块`。
