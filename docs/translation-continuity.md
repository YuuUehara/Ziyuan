# 连续翻译：备份、原文更新、跨章待查与交稿

本页对应 1.15.0；发布与验证进度见[验收记录](acceptance/1.15.0.md)。1.14.0 已能导出保留文学标记的 HTML 成稿，1.14.1 在网页「章节导出」补上同一选项。1.15.0 让原文追加与修订接受 Markdown、DOCX 和 EPUB。这些本地整理入口不调用模型。保存资料、处理待查和导出文件都不会替你准奏或御览定稿。

界面中的“预检”是交稿前检查；“指纹”是本次预览的核对码，材料变了就必须重新预览；“失效”表示先前的批准或判断已不能用于当前材料，需要重新核对。

工作台入口为主导航「译书」或 `/#translation`。「译稿」用于编辑与核对；人物、术语和记忆放在「资料」；通读、预检和下载放在「通读交稿」；新建、导入、原文更新及备份恢复放在「项目管理」。切换页签不会清空未保存的编辑内容。

## 完整备份与迁机恢复

在「项目管理」展开「备份与恢复」，先预览全部项目清单，再确认下载。由于审批共用事件簿，备份包含全部文本项目及共用朝廷历史（可能含代码任务正文），不是单本书的分享包。原件、译稿、草稿、标记、上下文、人物术语、版本、评论和待查历史随对应数据目录保存；登录令牌、模型凭据配置文件、缓存及锁文件不打包。

```text
ziyuan text backup
ziyuan text backup --output D:/backups/books.tar
ziyuan text restore D:/backups/books.tar D:/books-restored
ziyuan text restore D:/backups/books.tar D:/books-restored --yes
```

不指定输出文件时，备份命令只显示清单。恢复命令也默认只检查备份是否完整，确认后加 `--yes` 才写入文件。目标必须是尚不存在的新目录，父目录须已存在。软件先在临时目录检查项目和审批历史，全部通过后才将它改名为目标目录；失败时可能留下 `.ziyuan-restore-*` 临时目录供排查，不会覆盖目标。

Web 可上传备份，先校验，再输入英文新目录名确认恢复到当前工作区之下；随后从新目录启动紫垣继续使用。备份上限为 256 MiB、20000 个数据文件。发现符号链接、不安全路径、文件名大小写冲突、损坏项目或尚未完成的写入时，会停止操作并说明原因。观政账号只能查看，不能导出完整备份或恢复。

## 原文追加与修订

Web 展开「追加与修订原文」，选择 TXT、Markdown、DOCX 或 EPUB。默认追加新章；勾选「修订当前章」则改当前块所在的那一章。先看差异，再确认。

```text
ziyuan text source-update <项目ID> next.txt
ziyuan text source-update <项目ID> next.md --confirm <预览指纹>
ziyuan text source-update <项目ID> revised.docx --chapter c0001
ziyuan text source-update <项目ID> revised.epub --chapter c0001 --confirm <预览指纹>
```

预览后，只要项目、输入文件或引用材料有变化，就要重新预览；不能重复使用旧的确认码。旧原件和旧译都会保留，更新前的项目清单存于 `source-history/`。原文有实际变化的块需要重新送审、勘校和定稿；只改空白、正文内容未变的块不会因此作废。

TXT 和 Markdown 必须是 UTF-8，不超过 8 MiB。DOCX 和 EPUB 不超过 16 MiB；抽出来的正文如果超过 8 MiB，也会拒绝。这两种原件里最多 4096 个文件，每个解开后不超过 32 MiB，再多就拒绝。

修订时，段落数和每段所属的块必须与原来一样。拆段、合段或重排会被拒绝。已有译稿和批准不会被改掉；内容真有变化的块，要重新送审、勘校和定稿。

追加的 Markdown 整份算一章，不按标题再拆。修订 Markdown 时沿用这一章导入时的分章方式，结果仍须是一章。从多章文件里拆出来的一章，不能单独修订。按 TXT 或 Markdown 导入、带解析记录的项目，不能再用 DOCX 或 EPUB 追加或修订。DOCX 和 EPUB 只适用于当初按纯文本导入、没有解析记录的项目，抽正文的方式和首次导入相同。命令行 `text import` 导入的 TXT 没有归档原件；这种项目即使用 DOCX 或 EPUB 修订，也只改正文，不新建原件。已经有 `source.docx` 的，单章修订只接受 DOCX；已经有 `source.epub` 的，只接受 EPUB。换成另一种格式会拒绝。同一种格式、而且项目只有这一章时，先按内容摘要把旧原件放进 `source-history`，再覆盖同名文件。抽出来的正文即使相同，原件字节变了也要重新确认。追加新章，或者项目不止一章时，已有原件保留，这次只改正文。已批准的词证对不上，或相关块还有没做完的模型任务，会先拒绝。

## 跨章待查

Web 展开「跨章待查」，读取当前项目段落，选择问题所在段及相关前后文，填写核对事项和问题说明后登记。可以从问题跳回相关编辑段，并填写理由，将其标为待查、确认问题、有意异译或已解决。

每条待查都会保存当时的相关原译文、已批准资料、处理理由和历史。材料变化后，旧处理结果会标为过期：先点「重新核对并转待查」，读过新材料后再决定如何处理。相同材料和问题不会重复登记。没有待查记录只表示你尚未登记问题，不能据此认定全书一致；待查功能也不会自动识别人、修改译文或准奏。

```text
ziyuan text issue list <项目ID>
ziyuan text issue add <项目ID> issue.json --confirm <列表中的fingerprint>
ziyuan text issue review <项目ID> <问题数字ID> review.json
```

登记文件示例：

```json
{"paragraph":"c0001-p0001","related":["c0002-p0001"],"rule":"人物称呼","body":"两处不同称呼是否有意保留？"}
```

复核文件需填写列表中的最新 `record.version` 和该问题的 `fingerprint`：

```json
{"version":1,"fingerprint":"替换为当前问题指纹","state":"intentional","reason":"说话者与关系不同","recheck":false}
```

`state` 可为 `pending`、`confirmed`、`intentional`、`resolved`。过期记录先使用 `state=pending`、`recheck=true` 明确重新核对。关联段最多 16 项，历史最多 10000 条。

## 通读与交稿预检

Web「整章通读与交稿预检」连续显示全书或所选章的原译文，可定位回编辑段。译文注音、着重、粗斜体沿用现有标记渲染。这里显示当前译稿文件中的文字，人工草稿请回编辑器查看；是否已经准奏或定稿仍以块状态为准。

```text
ziyuan text read <项目ID> --chapter c0001
ziyuan text preflight <项目ID> --format html --chapter c0001
```

预检支持 TXT／Markdown／HTML，会按实际导出规则检查缺稿、版本失效、未定稿及格式无法保留的标记，同时列出过期或未处理的待查事项。页面会分开显示“必须先处理才能导出”的问题和仅供核对的提醒。把待查标为已解决不会自动定稿；准备交稿时仍从「章节导出」导出，软件会再次核对材料。

## 全文检索与草稿替换

网页「全文检索与草稿替换」按原文、现行译文、人工草稿或历史译稿范围查字面片段。原文检索也覆盖尚未翻译的段落；结果可定位回编辑段。历史译稿只是参考，不因检索命中而成为当前译稿。

只对人工草稿提供替换：在命中项填写替换文字，先检查本段替换前后内容，再明确确认保存。材料或修订变化后须重新预览；与文学标记相交的替换会拒绝，其他标记按正文变化调整位置。不修改批准稿，不自动送审、准奏或定稿。

## 翻译记忆与评论管理

「翻译记忆」可新增、修改、删除原译文对及记录采纳。采纳只是本地记录，不会替换正在编辑的译文，也不代表你已允许把它发送给模型。评论可回复、指派、标记解决或重新打开；这些操作都不改译稿和审批。

「翻译记忆交换」支持纯文本 TMX：先选文件，预览来源／目标语种、重复项和导入数量，再确认合并。导入不覆盖已有记忆或译稿；文件含复杂行内标记、DTD（XML 文档类型定义）等不支持内容时会明确拒绝；这里只交换文字，不保留完整排版。

## 文档与字幕入口

在「项目管理」的「导入文档或字幕」中，可向空项目导入 DOCX、EPUB 或 SRT，导入前须选择对应格式并确认。原件上限 16 MiB。DOCX 和 EPUB 里最多 4096 个文件，每个解开后不超过 32 MiB。在「通读交稿」的「导出文档或字幕」中下载成稿，导出使用有效定稿；目标格式无法保留译文标记时拒绝，避免下载看似成功却丢失标记。需要保留完整译文标记时，在原成稿导出入口选择 HTML。

HTML 成稿是可离线打开的正文文件，保留译文注音、着重、粗斜体和同范围叠加样式。它不承诺照搬原 DOCX／EPUB 的分页、脚注或浮动对象；原排版仍保存在归档原件中。

## 命令行检索与记忆交换

```text
ziyuan text search <项目ID> 片段 --scope all
ziyuan text search <项目ID> 片段 --scope draft
ziyuan text tmx export <项目ID> --output memory.tmx
ziyuan text tmx preview <项目ID> memory.tmx
ziyuan text tmx import <项目ID> memory.tmx --confirm <预览指纹>
```

检索范围可选 `all`、`source`、`translation`、`draft`、`history`，最多返回 200 处，结果截断时须缩小范围。命令行草稿替换用 `text draft-replace <项目ID> request.json`：请求含 `block`、`paragraph`、`from`、`to`；默认只预览，确认时补上预览返回的 `fingerprint` 与 `confirm: true`。替换只针对该段，不能修改批准稿；文学标记相交时须回编辑器手工核对。
