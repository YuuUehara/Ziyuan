# 稳定性约定（1.0.0 已生效）

1.0 起，下列对外接口只增不改：可以加新的子命令、参数、字段与事件，但已有的不改名、不改义、不删除。确需破坏兼容时只在下一个主版本（2.0）进行，并在 CHANGELOG 的「兼容性」一节写明。实验性功能及内部实现的例外见下文。

## 冻结的接口

| 接口 | 约定 |
| --- | --- |
| 事件簿 `.ziyuan/court.log` | 格式 v1。新版总能读旧版写下的事件簿（有逐版样本的测试为证）；新增事件或行尾追加的可选字段不升格式版本。旧版读到新版写入的内容时提示升级，`ziyuan migrate` 指出至少要哪一版。 |
| 外藩名册 `.ziyuan/mcp.json` | `servers` 下每个服务写 `command`（可带 `args`、`env`、`haoshe`；`haoshe.network` 为布尔或域名列表）或 `url`（可带 `headers`），二者择一；值中的 `${VAR}` 取自环境。 |
| 令牌 `.ziyuan/web-token`、`.ziyuan/web-viewer-token` | 32 位十六进制，可带换行；内容不合格时重新生成。 |
| 考题 `.ziyuan/exam/*.txt` | 题目（可带「题：」前缀、可多行），其后一行「要点：甲；乙；丙」。 |
| CLI 子命令与参数 | 见 `ziyuan help`。「恢复默认」统一写 `default`，「一件不授」统一写 `none`；`all` 只用于票拟、批红、复核、复勘、回报等可逐件重做的批量操作，落盘、评定、撤销必须逐件进行。 |
| `--json` 输出 | `court`、`officials`、`tasks`、`history`、`records`、`migrate`、`flags`、`mcp`。字段只增不删、不改义；键的顺序不作保证。`court` 与 Web 的 `/api/state` 同构。 |
| 退出码 | 0 成功；1 运行中出错（如诏令不存在、事件簿读不了、模型调用失败）；2 用法错误（未知命令、参数不对）。管道提前关闭与 Ctrl-C 退朝视为成功。 |
| 环境变量 | `ZIYUAN_LLM_MODEL`、`ZIYUAN_LLM_BASE_URL`、`ZIYUAN_LLM_API_KEY`、`ZIYUAN_LLM_PROVIDER`、`ZIYUAN_LLM_PRICE`、`ZIYUAN_LLM_RETRIES`、`ZIYUAN_MAX_STEPS`、`ZIYUAN_CONTEXT_TOKENS`、`ZIYUAN_TEST_COMMAND`、`ZIYUAN_SANDBOX`、`ZIYUAN_SANDBOX_ALLOW`、`ZIYUAN_DELTA`、`ZIYUAN_TZ`、`ZIYUAN_GITHUB_REPO`、`ZIYUAN_GITHUB_TOKEN`、`ZIYUAN_CONFIG_DIR`。 |
| Web 驿站 `POST /api/courier` | 凭令牌（`Authorization: Bearer`）投递 `{ text, department?, station?, urgent? }`，只入队。 |

`ZIYUAN_CONTEXT_TOKENS` 为旧工具输出的节略触发阈值（正整数，默认 48000），不是模型硬窗口或度支预算；最近四份输出仍受保护。`ZIYUAN_DELTA` 指定可选 git-delta 可执行文件；未设置时查 PATH，不可用时回退内置预览，不改变逐段审批语义。

- **事件簿**：仍为格式 v1，**没有新增事件类型**，`readable_since` 不变（最高仍为 1.2.0）。旧事件簿照常可读，无需迁移；1.2.0 及更早的二进制也不会因为本版新增的内容而拒绝读取事件簿。

- **新增内部文件**：`.ziyuan/write.lock`（写锁）、`.ziyuan/write.generation`（世代号，十进制加换行，偶数为空闲）、`.ziyuan/write-protocol`（写入协议版本，当前为 `1`）、`.ziyuan/recovery.json`（恢复记录，带格式版本与 SHA-256 校验）。四个都**不在冻结范围内**，格式暂不冻结，变化写进 CHANGELOG。损坏或由更新版本写入时会报错，不会重置为空。
- **旧版不能安全使用这些工作目录**：1.2.0 及更早的版本不认识这些文件，也不会据恢复记录阻断写入。**不要用旧版本写入由 1.2.1 管理过的工作目录**，否则恢复记录可能与实际状态对不上；确有需要时先把该目录的 `.ziyuan/recovery.json` 核对清楚。

## 1.2.2 新增

- **事件簿**：仍为格式 v1，**没有新增事件类型**，`readable_since` 不变（最高仍为 1.2.0）。旧事件簿照常可读，无需迁移；1.2.0 及更早的二进制也不会因为本版新增的内容而拒绝读取事件簿。
- **CLI**：新增 `ziyuan text recovery temps [--json] [--yes]`，默认只预览。全部是新增，没有改名、改义或删去已有子命令与参数；既有命令的 `--json` 字段一个也不变。
- **新增控制文件**：`.ziyuan-lease-<id>`，建在目标文件所在目录（不在 `.ziyuan/` 内），`<id>` 为 32 位小写十六进制，内容一行 `ziyuan-lease v1 temp=<临时文件名> id=<id>`，由写入者随用随建、改名完成后删除。它可以随时重建，不是用户数据，**不在冻结范围内**；留下或丢失只影响清理判断，不影响译稿、恢复记录与事件簿。
- **准奏顺带清理**：`apply` 在每个目标所在目录内先清可证明陈旧的临时文件，再落盘。行为与输出字段的其余部分不变，清理诊断走 stderr（命令行）；TUI 占着备用屏，写 stderr 只会被下一次重绘抹掉，改为在状态栏那一行追加条数「（N 项临时文件未能清理）」，路径与原因只在 `text recovery temps` 的完整报告里给。
- **只删能证明陈旧的项**：租约被活着的写入者持有、符号链接与 junction、目录、命名不符者与恢复记录引用项一律保留；`--yes` 只授权删除通过全部核对的项，不是强制删除，也不按文件年龄或 PID 猜测。
- **退出码**：沿用冻结约定——跑完为 0（包括预览里列出可清理项），扫描／删除的 I/O 失败与读不了的目录为 1，用法错误为 2。这里有意与 `text recovery status` 不同：`status` 的 1 表示「状态读到了，但还有未收尾的写入」，清理的 1 只表示「这一轮没跑完」。

清理的已知限制如下，按实际情况写明，不声称已覆盖：

1. 极窄窗口：`create_new` 之后、整行内容写完之前被强杀，会留下内容不可解析、未加锁、也不指向任何临时文件的租约残片。清理器无法证明归属，按 `LeaseUnparsable` 永久保留并报告，须手工删除。这里有意选择泄漏而非误删：残片只有几十字节，误删会让活跃写入失去归属证据。
2. 同一目录里只要有一份读不懂或版本未知的租约，该目录本轮的临时文件候选就都不会删除（`LeaseUnknownVersion`／`LeaseUnparsable`／`LeaseIdMismatch`）。宁可不动也不误删的代价是：一份坏租约会让该目录暂时不能自动清理，直到手工处理掉它。
3. 1.2.1 及更早留下的临时文件没有租约，一律报 `TempWithoutLease`，永不自动清理；早期版本写下的残留只能手工确认后删除。
4. 临时文件名回收再用：租约只记录文件名，不记录文件对象身份，「删除临时文件后同名重建」的竞争未验证，本版不处理。
5. 同一进程内的活跃写入不在本协议覆盖范围内：租约只解决跨进程归属判断。
6. Windows 上持有锁并不阻止别的进程改名或删除（std 默认共享模式允许），协议是协作式的，不承诺抵御不受信任进程的并发替换。
7. 符号链接与 junction 形态的候选／租约只用「不是普通文件」这一条覆盖，本机只验证了目录形态；非符号链接的目录重解析点（如云占位符）仍能通过 `is_dir()`，类型判断依赖 `symlink_metadata`。
8. 硬链接数异常既没有定义为保留原因，也没有检查，本版不声称覆盖。
9. **文件系统不支持文件锁时，这个工作目录里写不进去。** 租约靠 `File::try_lock` 加锁；锁不可用（`try_lock` 报错而非“被别人占着”）时 `Lease::hold` 直接失败，于是**每一次受管写入都会失败**，包括与清理无关的准奏落盘——租约在写入路径上，不只是清理路径。部分网络文件系统属于这种情况。这是有意的取舍：没有锁就没有归属证据，宁可拒绝写入，也不留下谁也证明不了陈旧的临时文件。

本项目自身的两处残留，一并写明：

- 恢复记录读不出来时，**自动**清理在这一轮整轮跳过（失败关闭），报告为路径 `.` 的一条 `Problem`——它绝不在猜的状态下删除任何东西；手工命令此时直接以退出码 1 结束，并在错误里说明「一份都没删」。
- 恢复记录里因为「目标内容已等于新内容」而被略过的目标，不在该轮的受保护集合内。这类目标没有待写入的字节，但理论上仍少了一层保护。

## 1.3.0 新增

- **事件簿**：翻译记忆不新增事件类型，不改变格式 v1，也不提高最低读取版本；原文、译稿与批准记录仍是依据，查询缓存不是新的批准记录。
- **CLI**：新增 `ziyuan text memory status|build|search`，均支持 `--json`。建库与搜索可用重复的 `--project` 逐个允许其他项目，默认只有当前项目；搜索须给 `--query`，`--limit` 默认 5、范围 1–50。没有修改已有命令、参数或输出字段。用法见[翻译记忆](memory.md)。
- **退出码**：沿用 0／1／2；状态查询发现尚未建库为 0，没有可用提供方时建库或搜索为 1，缺查询文字或条数不合法为 2。不可用不等于没有命中。
- **配置**：新增 `ZIYUAN_MEMORY_PROVIDER`，未设置、空值或 `none` 均不启用计算，显式设为 `local` 才使用本地 `char-hash-v1`。它不继承聊天模型配置，不回落到远程地址；本版没有远程嵌入提供方。
- **范围与有效性**：只提供当前有效定稿的段落，读取时重查资格；退回与版本失效的旧缓存不能继续充当有效译法。先按工作目录、明确允许的项目、语种对与内容种类过滤，再为候选计算相似程度；计算方法不符时须重建，不能混用。
- **不冻结的部分**：`.ziyuan/memory/` 是可丢弃、可重建的缓存，格式不冻结；`text memory` 的 JSON 字段与其他 `text` 命令一样暂不冻结。`ziyuan-memory` 的 Rust API 是内部实现，不按独立语义版本承诺兼容。格式或字段变化写入 CHANGELOG，不影响既有冻结接口的约定。
- **不是质量保证**：本地字符方法不是语义模型，分数只是排序依据，没有确定文学适用门槛。参考不会自动采纳，也不获得额外写入权限。后续方法与质量、费用预算须先登记，再经双语人工评测，不能把工程测试当作文学收益证明。

## 1.4.0：原文预览与确认导入

本页按 1.4.0 更新。版本提交的六项跨平台 CI 已通过；发行包与注册表结果分别见[版本验收](acceptance/1.4.0.md)。以下描述兼容边界，实际操作见[文本工具](text-projects.md)。

- **CLI 增量**：新增 `text preview`，以及 `text import` 的 `--ruby`、`--heading-level 1|2`、可重复 `--chapter-title` 和 `--confirm <预览指纹>`。不带新选项的纯 TXT 导入仍走旧路径，不改变既有含义；新解析须先人工检查预览再确认。原文、顺序、选项、标题或来源改变，须重新预览，不能沿用旧指纹。每项目仍只导入一次，不追加、不覆盖。
- **项目清单外壳**：新写入 `.ziyuan/text-projects/<项目>/project.json` 使用 **schema 2**。新应用可读取 schema 1 的旧 TXT 项目，不重新解析原件、不改变章段 ID 或既有提示字节；旧 1.3 无法读取新写入的 schema 2，**必须升级**。这是内部文件格式变化，不是朝廷事件簿迁移；`ziyuan migrate` 的事件检查不代表旧程序能读该项目。清单与 `text` JSON 字段仍不冻结，遇到损坏或更新格式报错而非重置。
- **原文块与译稿**：清单外壳版本不同于块／候选译稿的 `schema_version: 1`。原文段落新增可选 `inlines`，注音携带配对的 `base`／`reading` 与原件字节偏移；空字段不序列化，保留旧块编码。目标段落只写 `id`／`text`，不复制注音或偏移，不自动套用到中文；不保证模型质量。原件字节（包括 BOM）保留，派生正文跳过开头 BOM，不猜编码。
- **资源边界**：新导入原件合计最多 8 MiB、清单最多 32 MiB，完整编码的开销可能使清单更早触限；默认 48 KiB 提示块计入 JSON 包装、转义与注音字段。Web 上传完整 JSON 请求上限 2 MiB，比应用层原文上限更紧；Web 页面及内部 API 仍不冻结。
- **事件与范围**：导入本身不新增朝廷事件，不改变 `court.log` v1 或最低读取版本。支持保守的 TXT／Markdown 预览、可选注音与空项目确认导入，不承诺完整青空／站点方言兼容。成稿导出及参考绑定分别见下文，不要把导入的事件边界推广到整版。

## 1.4.0：成稿导出

导出本身不新增朝廷事件、不改变事件簿最低读取版本；不修改原文、译稿、审批状态或译文记忆资格。schema 2 边界仍有效，不能据“只读导出”宣称旧 1.3 可读新项目。

- **新增 CLI**：`text export-originals <项目ID> [--chapter <章ID>]... [--output <new.tar>] [--json]` 与 `text export-finished <项目ID> [--chapter <章ID>]... [--format txt|md] [--layout chapters|book] [--output <new.tar>] [--json]`，后者默认 txt／chapters。无输出参数为只读文件／警告／清单预览，指定输出时重新检查。旧的模型材料导出含义不变；`text` JSON 字段与导出清单仍暂不冻结。
- **资格与一致性**：只导出当前有效 Finalized，重查原文、译稿、已批准上下文、朱批、结构与定稿来源；成稿收集前后重新回放并比较双快照，原件也双读核对。不指定章节选全部，子集依项目顺序；未知／重复 ID 拒绝，所选范围缺块、待审、退回或失效整批拒绝。不保证导出后的快照始终代表当前状态。
- **内容边界**：原件按归档路径去重，字节不变；选单章可能取回包含其他章的整个源文件。成稿 TAR 含 TXT／MD 与 `manifest.json`；MD 模板保留块级代码和分隔线原位置，安全转义译文，不套源注音或图片／链接目的地址。原段含行内代码时因逐段译稿没有位置锚点而拒绝 MD，不悄悄丢代码；TXT 仅正文并警告代码／排版损失。仅批准译文本身的结构化 ruby 与正文一致且可安全表示时支持输出。
- **单一原子发布不是沙箱**：CLI 父目录须已有，拒绝覆盖、`..`、符号链接目录链／目标及工作区 `.ziyuan`、`translations`、`.git`、`.jj` 下的目标；允许控制目录之外的绝对路径。完整 TAR 在同目录临时文件写完并刷盘后以硬链接不覆盖发布，防止可见的半本书；不支持硬链接则失败，不退化为复制／覆盖。正常退出清理临时文件，不承诺强杀无残留、断电持久性或抵御恶意目录并发替换；依赖可信父目录与文件系统。
- **Web**：共用应用层资格与快照，先预览文件及警告、确认后重新检查下载，viewer 可只读使用，不授写权。`GET /api/text/{id}/export` 接受 `kind=original|finished`、`format=txt|markdown`、`layout=chapters|book`、逗号分隔 `chapters`、`preview=true`，非预览为 TAR 附件；Web 不接受服务器目标路径。页面与内部接口仍不冻结，详见[导出指南](text-projects.md#unreleased--14-第二批源码原件与成稿导出)。

导出不证明文学质量提高。操作见[导出指南](text-projects.md#unreleased--14-第二批源码原件与成稿导出)，最终工程及发行结果见[版本验收](acceptance/1.4.0.md)。

- **不新增朝廷事件，不提高最低读取版本**：版本快照、清理、格式回填、本地记忆、评论与 SRT 都不写 `court.log`，不改变已准奏、已定稿或恢复记录的含义。快照不是批准凭据，也不能代替 `zh.json`。
- **快照位置与格式**：`.ziyuan/text-projects/<项目>/versions/<块>/` 下的 JSON，含 `format`、`state`（`draft`／`approved`／`finalized`／`manual`）、逐段译文与标记。旧版不认识此目录，删掉不影响译稿、上下文与事件簿；本版把快照当辅助材料，损坏的单份快照在列表里跳过，不阻止其余快照或译稿可读。同状态同内容不重复写；自动快照写入失败不回滚已完成的保存、准奏或定稿。
- **清理会永久删除**：自动清理只保留每种自动状态最新 3 份；`version prune` 与 Web 清理默认只预览，加 `--yes`／再次确认才删除，手工快照默认保留。删除不进入回收站、不写事件；未知文件、符号链接与快照目录外路径不动。被删快照无法从事件簿重建正文，需要时先用 `compare` 或手工保存。
- **原件与回填**：`import-docx`／`import-epub` 在导入成功后把原件字节复制到 `.ziyuan/text-projects/<项目>/source-docs/`；原件不改，删除该副本只影响回填，不影响项目正文。`export-docx`／`export-epub` 先按 `export-finished` 同一套资格检查全部块有效定稿，再按原段落顺序写回；段落数、段号或空译不符、输出已存在、父目录不存在时整批拒绝。粗体、斜体、表格、图片与 EPUB spine 顺序保留，但按文字节点长度比例分配译文只是近似，不保证复杂版式、脚注、浮动对象或出版排版；DOCX 嵌套段落与 EPUB `script`／`style` 文字明确不处理。
- **术语表字段**：CSV／TBX 新增类别、范围、可用起点、读音、证据、关联术语、声线及称谓规则；旧八列 CSV 仍可读，任一行无法解析即整批拒绝，不静默丢字段。导入只合并本地资料草稿，仍需既有 `text context prepare` 与 `text context approve`，不因此获得外发或批准资格。
- **本地记忆与评论**：`tm.json`、`comments.json` 只服务当前项目；命中不自动替换译文，评论不改译稿、不批准、不外发。删除这些文件只丢本地记忆或评论，不影响原文、译稿与事件簿。
- **SRT**：导入写入项目正文并在 `srt.json` 保存时间轴；导出要求现行译稿段数与字幕数一致，不解析样式或时间码编辑。导出文件不覆盖已有路径。
- **Web**：`GET /api/text/{project}/blocks/{block}/versions`、`POST` 同路径、`GET …/versions/{id}?against=current|draft`、`POST …/versions/prune` 均为页面接口；观政可列表与对比，不能保存或清理（写接口 403）。页面与字段不冻结。

## 1.14.0：连续翻译与本地交付

- **本地整理不授予审批资格**：待查处置、记忆采纳、TMX 合并、草稿替换与通读都不等于准奏或定稿。预检复用成稿导出规则，实际导出再次检查。
- **备份与恢复**：备份覆盖全部译书项目和共用审批历史，排除凭据配置、缓存与锁。恢复校验路径、清单、哈希和项目结构，只写入不存在的新目录，不覆盖现有工作区；共用历史可能包含代码任务正文，分享前须核对。
- **原文更新**：UTF-8 TXT 仅支持追加或保持段数和分块归属的单章修订。材料指纹过时、结构化证据冲突或受影响任务未完成时拒绝；旧原件与旧译保留，受影响稿件须重新核对。
- **新增辅助文件**：原文历史、跨章待查、TMX 及检索结果不替代原译文、批准材料和事件簿。辅助文件仍是内部格式；旧版是否能打开原有项目不代表能安全处理新版本更新后的材料，更新前应备份并停止旧程序。
- **格式边界**：HTML 成稿保留译文注音、着重、粗斜体与同范围叠加样式；DOCX／EPUB／SRT 无法保留译文标记时拒绝导出。TMX 只交换纯文本记忆，不保证复杂排版或行内标记往返。具体限制见[连续翻译指南](translation-continuity.md)。

## 实验性

下列功能可用，但只用模拟服务测过，1.0 起不承诺兼容：行为、参数与凭据格式都可能调整，变化写进 CHANGELOG。用真实服务实测通过后转为冻结。

- **ChatGPT 订阅**：`ZIYUAN_LLM_PROVIDER=chatgpt`、`ziyuan login` / `logout` 及其凭据（变量名本身冻结，`chatgpt` 这一取值的行为不冻结）。
- **HTTP 外藩**：`.ziyuan/mcp.json` 中以 `url` 登记的 Streamable HTTP 服务（以 `command` 登记的本地服务已冻结）。

## 不在冻结范围内

- **库 crate 的 Rust API**：`ziyuan-core`、`ziyuan-app`、`ziyuan-memory` 等 crate 是 `ziyuan` 命令行的内部实现，版本号随整体走，但不按 semver 承诺 API。
- **给人看的文字输出**：措辞、排版、史官记随时可改；脚本请用 `--json`。
- **缓存与内部文件**：《大明会典》`.ziyuan/huidian`（对不上即重修，可随时删去）、翻译记忆 `.ziyuan/memory/`（可丢弃重建，不是原始资料）、执行者锁 `.ziyuan/executor.lock`、用户配置目录中的 ChatGPT 凭据与锁。
- **Web 页面与其余 `/api/*`**：供内嵌页面使用，可随页面改动。
- **测试用的环境变量**：如 `ZIYUAN_CHATGPT_ISSUER`。
