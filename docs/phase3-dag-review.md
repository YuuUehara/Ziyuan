# 1.0-RC Phase 3 DAG 修改速查表

## 改动概览

- `EdictDag` 是追加事件，与 `EdictSplit` 在同一提议中写入；旧事件不改。
- 写子诏令按 ID 自动串行，后一件须等前一件完成；只读子诏令仍可并行。
- 依赖未完成时不派工。上游失败或撤销会使下游保持受阻，不自动重试或降级；皇帝可撤销受阻子诏令，让尚书按各件结局汇总。
- 节点可携尝试次数上限、期限、度支、约定产出、另行批红要求与幂等键。到期或次数用尽时记失败；约定产出写入承办与汇总提示。
- CLI `--json`、Web `/api/state` 与 TUI 展示依赖及受阻状态。

## 主要落点

| 区域 | 改动 |
| --- | --- |
| `ziyuan-core` | `DagNode` 与 `CourtEvent::EdictDag` |
| `ziyuan-governance` | DAG 校验、自动串行提议、指派门控、批红与 `blocked_by` |
| `ziyuan-storage` | `DAG` 编码/回放、兼容性样本；最低读取版本登记为序号 12（`1.0.0-rc.2`） |
| `ziyuan-app` | 自动串行分办、期限/次数/度支检查、上游回奏与约定产出提示 |
| CLI / TUI / Web | 受阻状态、依赖与排程元数据展示 |
| 测试 | 校验拒绝情形、调度与失败阻塞、提示注入、API JSON、TUI 状态徽章 |

## 使用与边界

日常仍用既有分办流程：

```bash
ziyuan split 3
ziyuan split 3 4:改 storage 7:改 runtime
ziyuan run
```

写权限分办会自动串行。只读分办保持并行。`dag` 元数据目前没有 CLI 或 Web 编辑界面；自定义依赖、期限、尝试上限、度支、约定产出、批红要求与幂等键尚不能由用户在前端配置。幂等键目前只落盘，不代表外部副作用已有去重保证。

## 版本策略

`1.0.0-rc.1` 已发布；本次将工作区推进到 `1.0.0-rc.2`，并把 `DAG` 的最低读取版本登记为序号 12（`release_name(12) = 1.0.0-rc.2`）。正式版 `1.0.0` 应在之后取得新的序号。

## 请审阅的决定

1. **配置入口范围**：本阶段实现自动串行与运行时字段支持，没有提供用户编辑其他 DAG 元数据的命令或界面。若要在 1.0-RC 加入口，需另列范围。
2. **失败处置**：上游失败不会自动重试，也不会让下游降级运行；下游继续受阻，需皇帝撤销或另行分办。
