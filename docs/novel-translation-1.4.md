# 1.4 小说翻译需求草案：章节读写、日文注音与参考译法

状态：2026-10-31 已按确认方案实现第一批，完成 Linux orb 本地工程验收；仍为未发布源码，不是完整 1.4 已交付。第一批范围及证据见[验收记录](acceptance/1.4-first-batch.md)，实际用法与语法限制见[文本工具](text-projects.md#unreleased--14-第一批源码预览与确认导入)。

以已发布的 1.3.0 为基础，1.4 包含 TXT／Markdown 章节导入导出、日文 ruby／振假名支持及人工选用参考；分批开发验收，不包含远程记忆库或 Kakuyomu 接入。第一批已实现导入、预览确认和保守的注音支持；以下章节成品导出、参考选择及文学质量评估仍是后续需求，不是现有行为或发版承诺。

## 1. 用户要完成什么

把有权使用的 TXT 或 Markdown 小说按章导入，保留日文正文、注音、段落与出处；翻译或修订一个块时，查到以前认可的译法，自己决定选哪些，确认这些内容会交给当前配置的翻译模型，再为这一次任务下诏。之后仍按原有流程执行、审阅差异、准奏与御览；选了参考不代表译文已经获准。完成后将有效定稿按章导出为 TXT 或 Markdown，便于通读、校对及交付。

成功不以“模型照抄了参考”为准，而是：只有选中的、仍有效且获准使用的参考进入本次请求，出处可查，未选参考与旧流程不受影响。文学效果另行评估。

## 2. 现有能力与本次新增

1.3 已有有效定稿收录、范围受限的查询、失效核对及独立的 `reference_prompt` 文本导出；初译和修订仍不消费该导出。复用这些规则，不再写一套“看到定稿事件就算有效”的判断。

本次增加：

- TXT／MD 文件的章节导入、预览与顺序确认，以及不改变审批状态的章节成稿导出。
- ruby 的结构化保留、安全显示和模型输入；区分正文、读音、强调与普通括号。
- 用户为一个目标项目／块／初译或修订操作选择参考。
- 下诏前核对选择、形成这次任务专用的参考快照，预览外发内容及上限。
- 任务执行前再核对来源与内容，随后把这份已确认的参考交给模型。
- 在任务记录里查看当时使用的出处与版本，解释为何不能再沿用失效选择。

不增加自动检索、自动选中、自动准奏、自动术语晋升或后台批量翻译；`resume` 首批仍按旧规则续做，不自动带上上次或其他块的选择。只读审校也不自动接入这份参考，避免它替模型的初译背书。

### 2.1 章节导入：TXT 与 Markdown

**现状边界。** 1.3 的 `TextProjects::import_with_limit` 只允许向空项目导入一次，一文件一章，按参数顺序排列；按空行分段，保存原件与 UTF-8 字节区间。它不是 Markdown 或 ruby 解析器。现有翻译 `export` 导出的是模型材料，不是整章成稿；新入口必须与之区分，不能改变旧命令的含义。

首版建议：

- 接受 UTF-8 `.txt`、`.md`／`.markdown`；有 UTF-8 BOM 时保留原件，只在派生正文中处理 BOM。非法编码明确报错，不静默猜测 Shift-JIS 或替换乱码。CRLF／LF 差异不破坏原件追溯。
- 默认一文件一章，按用户确认的顺序而非文件名字典序导入；文件名提供默认章名，可另填章名。多文件可以混用 TXT 与 MD。
- MD 另提供显式的“按标题级别分章”模式：用户选一级标题或二级标题，先预览章节数量、顺序和标题前的内容归属；不能猜测标题前内容应丢弃。代码围栏、引用等内部的 `#` 不作章节标题。TXT 首版不自动猜测“第几章”，避免把正文误切开。
- MD 按结构解析，至少处理标题、段落、强调、列表、引用、分隔线、链接文字及代码围栏。段内软换行不变成新段；代码、链接目标和图片地址不交给模型改写，不下载图片或外链。保留结构及原文定位用于回填；尚不支持的节点给出位置与说明，不静默丢弃。章节题名保持原题，可人工提供译题，不假装正文译完就有了译题。
- 导入预览显示格式、章节与段落数量、注音识别结果及警告；确认前不发布项目变更。大小限制按完整编码后的块与清单计算，不能因剥离标记低估；超大段仍拒绝，不为塞进块而截断日文或注音。
- 1.4 首批继续保留“一次导入、原文不可原地替换”的承诺。追加连载章节、重排或替换已有章节另做设计；不顺带引入会改变旧章 ID、定稿资格和跨章上下文的更新机制。

CLI 与 Web 共用导入检查；Web 上传的文件名只作显示数据，不作任意写入路径。已有 TXT 项目仍按原有分段与身份解释，不因升级而重新解析成另一批段落；新版派生结构须有兼容与版本方案，不能改写原件或假冒旧项目已迁移。用户选择新解析规则时须显式新建导入，不自动改变旧译稿归属。

### 2.2 日文 ruby、强调与 Unicode

**三层分开。** 归档原件逐字节保留；派生数据关联“基底正文、读音、原文范围”；界面、模型与导出各自生成表示。不能先用正则删标签再假定信息仍在，也不能只把读音留下、把汉字正文丢掉。正文与读音是一组，不得被分块拆散；原文范围仍指向原始 UTF-8 字节，不指向去标记后的字符串。

首版支持的明确写法与边界：

| 输入 | 处理契约 |
| --- | --- |
| `｜漢字《かんじ》`、`\|漢字《かんじ》` | 显式标明基底的注音；允许基底是汉字、假名或混合文字。 |
| `漢字《かんじ》` | 仅在用户启用相应日文注音解析规则时，以紧邻的连续汉字为基底；跨标点、假名或段落的歧义不得猜测。组合字符与日文迭代符的归属须在实现前列出规则和样例。 |
| `<ruby>漢字<rt>かんじ</rt></ruby>`，含可选 `rb`／`rp` | 仅解析可验证对应关系的简单结构；`rp` 是回退括号，不并入正文。多组、嵌套或复杂跨组结构若未支持，原样保留并提示，不能错配读音。 |
| `《《強調》》` | 识别为强调而不是 ruby；与 MD 自身强调分别解析，不把内容当读音。 |
| `漢字（かんじ）`、`漢字(かんじ)` | 默认普通括号；首版不自动推断为注音，避免误吞对白、解释和异读。 |
| 不闭合的注音、其他青空文库批注如 `［＃…］` | 保留原文并定位警告；首版不承诺兼容整个青空文库／小説家になろう格式。可改为普通文本导入，不静默清洗后当作完整支持。 |

TXT 默认普通文本，注音解析须显式启用并预览；MD 的日文文本注音也须选择规则，HTML ruby 仅进入上述安全子集。纯文本模式仍原样保存所有符号，不能自动把普通 `《…》` 当注音。解析器优先区分强调与注音，排除代码及链接目标；完整语法与错误恢复策略须在实施前固定，不以表中少数样例代替完整规范。

- Web 用受控结构生成 ruby 显示并提供“正文＋读音”的可访问文本；不执行源 HTML，不加载其脚本、样式、图片或外部资源。其他 HTML 不直接传给 `innerHTML`；预览与下载均防止源内容变成可执行页面。
- 模型材料同时携带基底、读音及对应关系，注明它们是原文资料而不是指令。只发汉字会丢失人名读法、双关或反讽，只发读音又会丢失词义；两种错误都须由实际请求捕获验收。标记占用的真实字节也计入容量。
- 不自动将日文注音套到中文译文，不要求每条读音都变成译文括号。特殊异读、人物称呼或双关由译者结合上下文处理，仍走审阅、术语／朱批和批准流程；首版不增设自动音译、注音生成或词典服务。
- 保留长音、促音、小假名、踊字、半角假名和组合浊点。不默认 NFKC 化或统一异体字，不在组合字符中间切断；任何检索用规范化不回写原件，算法变化须使相关派生索引失效并可重建。
- 首版不包含纵排、EPUB、自动 ruby、浏览器插件或网站抓取。支持日文 ruby 不等于通过日文文学翻译质量验收。

### 2.3 章节导出：原件与有效定稿

- 明确区分“取回原件”与“导出译文”。前者返回归档文件，不声称格式转换后仍逐字节相同；后者按用户选择的章节及项目内顺序导出，支持每章一文件或合并成一本 TXT／MD。
- 译文仅使用当前仍有效的 Finalized 结果，重新核对原文、上下文、朱批与译文等资格，不只寻找最后一个定稿事件。所选章节有缺块、待审、退回或失效内容时，默认拒绝整个成稿导出并列出章／块原因；首版不以空白、原文或草稿悄悄补洞。
- 保留段落与章界。TXT 使用明确章名与空行；MD 用稳定层级标题并安全处理译文中的 Markdown 符号，不能把译文意外解释为图片、HTML 或链接。MD 导入保留的非翻译节点按原位置回填；跨格式转换存在的损失须预览说明，不能宣称任意 MD 无损转 TXT。
- 日文原件取回保持原记法。译文如确实含人工批准的结构化注音，TXT 用明确的 `｜基底《读音》` 表示，MD 用安全生成的简单 ruby；没有此类信息则输出普通译文，绝不从日文源头自动复制到中文句子上。首版不新增译文注音编辑器，普通括号照原样输出。
- 导出附机器可读清单：项目、章节顺序、原文／译文版本与摘要、定稿来源、格式及解析／导出规则版本。所选内容须形成可核对的一致快照；导出期间变化则重核或拒绝，不能混合两个版本却声称来自同一次定稿。
- 导出为只读操作，不写审批事件、不修改源文件、译稿或记忆资格。CLI 输出到项目控制目录之外的用户指定位置；拒绝路径越界、符号链接绕过及覆盖已有文件，失败不得留下看似成功的半本书。Web 返回安全文件名的下载；两端使用同一应用层资格与快照规则。

### 2.4 章节与日文必须通过的验收

使用自有或获准的短篇夹具，分别验证 TXT／MD、混合文件、非字典序章序、标题前内容、围栏中的假标题、空章、超长段、BOM、CRLF 和非法 UTF-8；空章须显式确认或拒绝，不能被丢弃或称为已完成翻译。已有 1.3 项目及事件仍可读，原件摘要、段号和定稿归属不变。

注音样例覆盖显式／隐式基底、混合假名基底、连续两组、强调嵌邻、普通括号、字面标记、破损／嵌套 HTML、危险属性与外链、组合浊点、迭代符及超限边界。独立给出预期的正文、读音、原文范围与输出，不能从解析结果反推测试答案；验证原件字节保留、模型实际收到成对信息、跨块不拆组，界面不执行外来 HTML。

导出验收覆盖部分章节选择、全部有效定稿、缺一块、定稿后手改、退回、导出并发变化、重复导出、既存文件／目录穿越与中途失败。核对实际 TXT／MD 内容、章序、段落、注音与清单，不只检查下载成功；导出前后原文、译稿和审批记录不变。CLI 与 Web 均覆盖，Web 还须在三主题、桌面与窄屏实际检查 ruby、长读音、预览警告及下载交互的截图／录屏与可访问性。

## 3. 一次完整操作

1. 选定目标块，在现有译文记忆区输入查询；没有启用记忆库时可继续原来的无参考翻译。
2. 查看每条原文、译文、项目／章／块／段出处和当前资格。分数只表示匹配程度，不叫可信度；不预选任何项。
3. 勾选想用的参考，查看所选清单与完整发送内容；可移除、全部清空，或返回无参考流程。
4. 点击明确区分的“使用所选参考初译”或“使用所选参考修订”。说明这里只入队，实际执行 `run` 或常驻执行器运行时才会调用模型。
5. 下诏成功后显示任务号及绑定的参考清单。不能用“模型已采纳”描述仅入队的结果。
6. 等待期间资料可能变化；执行前复核不通过时，不发模型请求，保留原稿并说明要重新查询、选择和下诏。不会自动替换成另一条参考。

切换项目、块或操作时清空当前选择；查询页刷新不得悄悄扩大或换掉选择。较早的异步请求不能覆盖新项目；选择所依据的资料改变时，标为需要复核，不假装仍有效。

## 4. 选择与授权

- 选择的是具体记录及版本，不是搜索结果的第几行。重排、换关键词或重建缓存后，不能把原来的“第 2 条”变成另一段。
- 目标绑定到本次项目、块和操作；其他块不能直接复用同一份选择凭据。相同记录重复勾选只算一条。
- 客户端只提交选择与期望版本，不能提交一段任意译文并声称它来自有效定稿。应用层重新读取并核对真实资料，不信任浏览器传来的资格或正文。
- 默认当前项目。CLI 沿用逐个授权跨项目的方式，且当前项目必须在范围内；Web 首批继续只支持当前项目，不在这次顺带开放跨项目界面。同语言及其他检索边界保持不变。
- 从本地查到参考不等于已经同意把它交给模型。使用所选参考的操作须明确告知：相关原文、译文及出处将随正常翻译请求外发至当前模型服务。不得为这次操作另行扩大读取目录或工具权限。
- 观政令牌只能按原有权限查看，不能创建带参考的翻译任务。未经允许的项目不能因高分、伪造选择或旧凭据混入。

## 5. 快照、排队与失效

每次任务保留所选记录身份、来源定稿、内容摘要、原译文快照、目标块和操作，足以回答“这一次到底用了什么”。派生索引不是批准凭证；不能只保存一个可被重建替换的缓存位置。

下诏与执行前均须核对：来源仍是当前有效定稿、原文／译文／上下文／朱批及来源版本未变、工作目录和授权范围相符。退回后即便再次定稿成相同文字，旧的选择也不能冒充对新版本的确认。

任一选中项失效或资料读取不稳定时，整次带参考操作停止，不悄悄少用一条、换一条或改成无参考调用。用户可明确返回无参考流程。缓存重建但资料身份、来源和内容都未变，不应仅因排名改变就误认为选了另一条。

这两次检查不能保证模型执行期间资料永远不变，也不能撤回已发送的内容。执行前有效、之后才发生变化时，保留发送时的真实记录，不能把旧快照显示成当前有效；准奏与定稿仍按现有规则核对。若要保证来源变化必定阻止定稿，须另行设计并实现引用依赖检查，不能在首批文档中假定已经具备。

持久化方式与事件兼容在实施设计时评审。不能为了保持“没有新增事件”的口号，把任务事实只放在可丢弃缓存中；也不能无说明地改变旧事件或被冻结接口的读写承诺。

## 6. 容量与提示边界

建议首批采用保守上限：每次最多选 8 条，最终参考材料完整编码后不超过 8 KiB；两项均为待确认的产品默认值，不是实测质量预算。搜索返回数量沿用原接口，不把搜索上限改成选择上限。

超限时展示已选数量、大小与上限，拒绝带参考下诏，提示减少选择；不截断半段译文，不自动丢弃末尾参考，也不挤掉当前原文、术语或朱批。空选择走原有无参考流程，不额外建立“使用了记忆”的记录。

复用现有参考文本的引用边界与出处格式，明确原文、术语与朱批优先；参考中伪装的指令仍只是引用。参考不会获得额外工具或写入权限。模型是否遵守仍须审阅，不能把提示包装说成绝对防护。

`ZIYUAN_CONTEXT_TOKENS` 只是旧工具输出的节略阈值，不是模型窗口或总费用上限；8 KiB 也不是精确 token 数。本批不自动猜测模型窗口，不承诺总请求一定装得下；真实服务拒绝、费用与输出长度仍按现有失败及审阅规则处理，并如实展示。以后若支持总输入／输出预算，应独立设计，不复用这个变量冒充硬限制。

## 7. CLI、Web 与界面边界

CLI 须能导出机器可读的候选身份与版本、明确选择子集、提交前检查和查看本次任务参考；不要求用户复制引用正文或编辑内部缓存。具体新增参数名、清单格式与错误码在实施设计时确定，现有无参考命令及其输出契约保持不变。不能把选择清单当作任意可执行文件或可跳出工作目录的读取入口。

Web 复用现有译书卡片和记忆区，不再另建一套项目导航。原文、译文、出处、勾选状态与外发说明均可查；提交中禁用重复操作，失败后保留可核对的选择。按钮禁用不是唯一去重措施：响应丢失时先按任务身份查询结果，不能直接重发一个可能已经生效的写操作。应用层须对同一提交身份与相同内容返回原任务，对相同身份但内容不同明确拒绝；它只保证下诏去重，不代表任意模型／工具调用具有去重保证。

界面验收包括三套主题、1280 像素桌面与 390 CSS 像素窄屏，长原译文、长出处、多选上限、空结果、加载、失败、失效与只读状态。内容在本框内换行，按钮不被挤出边界；键盘可勾选、移除、预览和返回。切换项目及周期刷新不丢失有效操作、不显示别的项目内容；更新截图与真实指针／键盘操作录屏。

## 8. 必须通过的验收

1. **旧流程**：不选参考时，初译、修订、审校、续做和批准写入行为不变。
2. **确实选中才发送**：候选甲乙丙只选乙，实际模型请求只能含乙；任务记录与请求来源一致。测试用可控服务捕获真实请求，不只检查文本组装函数。
3. **权限**：CLI 明确授权的另一项目可以使用；未授权、不同语言、伪造记录和 Web 跨项目输入均不能进入请求，观政创建返回拒绝。
4. **变化**：搜索后下诏前变化、下诏后执行前变化分别检查；覆盖退回、重定稿、手改译文、来源丢失、上下文或朱批变化。执行前拒绝时模型请求为零，不写原稿。
5. **稳定身份**：结果重排和缓存重建不偷换所选内容，旧版本确认不能批准新来源；伪造清单正文不能绕过读取。
6. **容量边界**：选中数为上限和上限加一、完整编码大小恰好达限和超限，使用非 ASCII 文本区分字符数与字节数；超限不下诏、不改事件记录或译稿。
7. **重复与恢复**：并发 CLI／Web、双击、响应丢失后查询／重试、重启后同一提交只对应一个任务；相同身份不同内容不默默覆盖。
8. **外来指令**：参考含伪造边界、命令或要求扩权时仍作为引用；真实工具权限与准奏门控不变。不得用模型碰巧没有服从来替代程序权限检查。
9. **界面与说明**：上述屏幕状态实跑、检查截图和录屏；指南明确已选、已入队、已发送与已批准四种不同事实。

工程验收后再做少量获准的日文、英文真实试译，登记模型、用量、费用与人审发现；未完成双语评估前，不声称改善长篇一致性或出版质量。

## 9. 开发与交付顺序

1. 确认范围与支持语法，评审原件／派生结构、旧项目兼容、引用持久化、执行前复核、提交去重和接口兼容；固定边界后才写契约测试。
2. 第一批实现 TXT／MD 导入、结构与注音保留；先验证原文范围、容量和旧项目不变，再接 CLI／Web 预览及安全显示。
3. 第二批实现有效定稿的 TXT／MD 成稿导出，共用资格检查并验证快照、文件安全与缺块拒绝；不复用模型材料导出冒充整章导出。
4. 第三批实现真实参考选择、快照与任务绑定、执行前检查；用捕获真实请求的本地服务验证，再接 CLI／Web，不复制应用层规则。与章节读写分开提交、验收。
5. 实跑跨前端并发、重启与失败恢复，再检查三主题／两种宽度，更新指南、截图和验收记录。
6. 小样本真实试译通过后，完整测试与跨平台 CI 均过，再独立准备 1.4 的版本登记与正式下载包验收；不修改已公开的 1.3.0 标签、crate 或资产。

Kakuyomu 只保留接入评估议题，目前没有确认可直接使用的官方作品订阅 API；本需求不包含网页抓取、账号登录、正文下载或自动翻译。章节追加与原文更新不在首批承诺内；若连载持续更新成为必要工作流，须先单独评审稳定身份、上下文变化及既有定稿的失效规则。
