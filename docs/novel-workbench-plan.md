# 小说翻译工作台：人物、术语与跨章一致性规划

日期：2026-11-02。状态：**待实施规划，不是已交付功能，不承诺版本或日期。** 本轮优先细化小说翻译方向；不将 Windows 原生号舍和代码索引的未完成事项视为取消，也不授权新的付费调用、推送或发行。

N0 的行为契约、人工审批兼容边界及自创三章验收样本已整理为[独立设计基线](novel-workbench-n0.md)。N1a-1 与 N1a-2a 已推送且各自六项原生 CI 通过，草稿及纯文本审阅快照不赋予批准资格。N1a-R1 已本地实现译文注音／圆点着重／粗斜体的草稿持久化并通过本地验收，尚未提交推送或原生 CI 验收，边界见基线第 11 节；仍无 CLI／Web 标记编辑、富标记候选或正式导出，不能宣称完整工作台已经交付。

## 1. 产品目标与已有基础

从 OmegaT 借鉴双语编辑、译段导航、参考复用与质量问题导航，但优先服务小说，不复制全套通用 CAT 功能。

目标：译者在同一工作台阅读上下文、编辑译文及其注音／着重等结构化标记、核对人物与术语、处理跨章疑点，经审批和定稿导出可通读且保留受支持排版信息的章节。既支持纯人工翻译，也保留 AI 初译／修订路径；不强迫每次改字都调用模型。这里的“类似 OmegaT”指译者主导的 CAT 工作流，不表示 OmegaT 原生支持这里的全部文学标记，也不以外观相似代替功能。

已有基础：稳定段落 ID、章与提示块、TXT／Markdown 与受限 ruby、三栏只读对照、批准上下文（词表／文体／章节摘要）、朱批、词证、逐段勘校、定稿失效检查、本地记忆与人工选择参考。当前并无人工译文工作台、结构化人物关系库或完整跨章检查系统。

实现前核对的主要来源：`ziyuan-app/src/text_project/{model,split}.rs`、`translation/{context,status,verification,session,finished,references}.rs`、`ziyuan-memory/src/{pair,search}.rs` 以及 Web 文本入口。详细盘点见本线程 OmegaT 调研记录；历史工程边界见 [1.4 第三批](novel-translation-1.4-third-batch.md)与[文本指南](text-projects.md)。

## 2. 小说专属规则

### 人物：实体不等于名字字符串

- 为项目内人物分配稳定身份，记录原名、读音、别名／绰号、允许译名、说明、原文出处与确认状态。合并或拆分人物身份必须人工决定，不能因同名自动合并。
- 称呼规则至少能说明“谁称呼谁”、叙述或对话、适用章节／段落范围、允许表达与依据；未知说话人允许保持未知，不自动归属。
- 人物口吻先采用带原文例句与适用范围的简短说明，例如自称、敬语、句尾习惯和刻意破格。自动检查不宣称能证明口吻正确。
- 同一人物不同阶段、不同说话人的称谓可并存；隐藏身份、真名揭示、关系变化按叙事出现范围处理，不用后章结论覆盖前章表达。
- 首版不是人物知识图谱：不自动推理亲属关系、说话人或时间线。故事内年代与章节顺序分开，倒叙不能仅靠章号判断。

### 术语：复用词表，补足可执行的适用范围

- 复用现有词表的原文、允许译法、备注与批准快照，不再建立第二份相互竞争的正式词表。人物卡引用术语条目，而不是另存一份权威译名。
- 现有 `scope` 是自由文本，不能静默解释成机器规则。新结构化范围需有格式版本、旧项目兼容策略，并区分章／段范围、说话人条件与人工说明。
- 区分人名、地名、组织、物种／职务、文化词和普通词；词义依语境判定。命中只是候选，非命中不代表无问题。
- 草案、暂定、已确认和已批准用于任务是不同事实。模型提案不能自动晋升；有意异译记录理由与适用位置，不做全书无条件替换。

### 跨章一致性：先证据索引，再做检查

- 按来源章／块／段建立人物、术语及人工确认事实的出现记录；首版采用字面候选和人工关联，不把实体识别或向量模型当必要依赖。
- 每个问题给出当前段、相关前文、原译文短引、触发规则与版本、原因及局限；区分疑似冲突、待查、合理差异和确认问题。没有命中不能显示“全书一致”。
- 关系、时间线、指代和叙述视角首先以人工词证／勘校关联呈现；语义检查是可选建议，不以字符串规则推断情节真伪。
- 按目标位置筛选可供模型使用的资料，章内也要考虑揭示先后。未来章节信息默认不进入前章任务；回修时可显式选择，但要提示可能泄露后文并保留选择快照。
- 项目事实、作品中的角色认识与不可靠叙述不可混成单一“真相”；暂定判断不得自动覆盖原文。

## 3. 编辑与审批契约

- **文学标记是正文契约，不是最后补的 CSS**：区分注音基字／读音、着重号、一般斜体／粗体；可视编辑与可检查的标记视图对应同一结构。译文标记由译者显式保留、调整或删除，不按源文字符偏移自动套到译文。保存、提交摘要、冲突、恢复、批准、定稿和导出均须覆盖标记变化；无标记旧稿仍按原义读取。详细缺口与新验收样本见 N0 第 10 节。
- 默认沿用段落级身份，不重切旧项目；模型提示块继续是调度单位，不是人工编辑单位。句级拆合暂缓，避免改变已有引用与定稿归属。
- 人工稿独立于现行批准稿；保存需携带来源及基线修订，旧页面保存遇到冲突必须拒绝覆盖并保留可恢复内容。服务端持久保存与浏览器暂存状态明确区分。
- 人工稿提交为可审阅修订，不能通过保存直接改写 `zh.json` 并伪装已准奏。允许未完成段落存在于草稿；提交块级审阅时组成完整候选，继续通过现有结构检查。
- 纯人工路径不伪造模型任务、用量或双路审校记录。其审阅主体、批准事件与定稿条件需在 N0 明确设计，通过兼容检查后才能开发，不能为方便绕过现有权限或冒充旧 AI 流程。
- 保存草稿不自动撤销当前批准稿；批准替换后，旧勘校和定稿不得冒充当前结果。界面同时显示“现行批准版本”与“未提交草稿”。
- 人物／术语批准先沿用现有上下文版本及失效机制。第一轮不承诺精确到单条规则的最小失效范围，也不为了保住旧定稿而绕过现有保守判断。
- 前文材料改变时，保留旧任务当时所用快照并标明现已变化，列出需复核的引用。现有参考来源变化并不自动阻止后续定稿；若要新增依赖门控，须另批设计、显式说明，不能把提示暗称硬保证。
- 所有问题处理绑定原文、译文及规则版本。改稿后旧“已解决”不能直接沿用；结构通过、问题处理、人工复核与有效定稿继续分开显示。

## 4. 小批实施顺序

| --- | --- | --- |
| N0 · 契约与样本 | `translation/` 与项目模型所有者：人工稿生命周期、人物／词表引用、结构化范围、审批事件兼容、章节可见性；先不做通用知识库 | 明确纯人工批准／定稿路径，固定对抗样本及通过标准；旧项目和日志读取不变。格式、命令名此时审阅，不在本规划冻结 |
| N1a-R · 文学标记契约与应用层 | 在开放人工批准前，先定译文专用行内结构及格式能力矩阵；支持 ruby 与语义独立的着重标记保存、校验、摘要、冲突和恢复，保持源文／译文结构分离 | 标记独改可检出冲突；基字改变、嵌套／交叉及未知标记明确处理；完整往返不丢字／读音／着重，旧稿不重解释。按小批实现，不顺带扩建 EPUB／DOCX |
| N1a · 人工稿应用层 | 在 app 保存／恢复段落草稿、版本冲突检查、组成审阅候选，接既有受管写入 | 无模型可完成保存、重启恢复、提交审阅；冲突不丢内容、失败不留下假批准，批准前原稿与导出不变 |
| N1b · 最小双语工作台 | Web 双语及行内标记编辑、保存状态、上下文、下一未译、快捷键与章级进度；CLI 提供必要管理入口，TUI 如实显示能力边界 | 无需编辑 JSON 完成含注音／着重的一章人工翻译与审阅导出；桌面／窄屏、只读、长文、标记选择／修改、保存失败及冲突实际操作通过 |
| N2a · 人物与术语资料 | 应用层结构化身份、范围、出处与版本；复用批准上下文；界面编辑、预览与批准 | 同名异人、别名同人、不同称呼及揭示范围正反对照通过；旧自由文本 scope 不被误执行 |
| N2b · 段旁辅助 | 当前段展示适用人物／术语、字面出现候选与原文出处；候选人工插入、全文检索 | 例外可解释、不自动替换、不把人工关联当模型推断；规则变化后的旧结果可辨认 |
| N3a · 跨章问题闭环 | 可重建出现索引、版本绑定的问题报告、跳转、例外与复核记录 | 多章变化／重启后不显示旧报告为当前；可从问题跳回原译文，有意异译不会反复冒充未解决错误 |
| N3b · 通读与实测 | 整章连续阅读、跨章定位与待查清单，获准后做文学小样对照 | 工程与文学结果分别报告；未达到文学门槛不扩建语义系统、不宣称质量收益 |

N1a-1／N1a-2a 已验收。当前 N1a-R1 只做标记契约、草稿保存／恢复与纯文本提交阻断；下一小批 N1a-R2 做无损结构化候选及支持格式能力检查，再继续 N1a 的恢复／批准链路 → N1b → N2a → N2b → N3a → N3b；每批原生 CI 通过再继续。人物、术语和跨章规则继续保留，不因新增排版需求取消；实际界面排布在实施前另行探索，本页不选定视觉设计。

## 5. 必验样本与失败条件

使用自创或获权的连续三章小样，预先人工标注以下不同答案，不能拿实现输出生成预期：

1. 两个同名人物不能合并；一个人物的两个别名可由人关联。仅有文字相似不得自动认人。
2. 同一人物被上司称姓、被家人称昵称、在叙述中用姓名，三者应可合理共存；同一适用范围的错名应产生可定位候选。
3. 第一章匿名、第二章绰号、第三章真名，前章请求不得收到未来身份；显式回修选择后文与默认选择应有不同外发快照。
4. “狸／狐狸”、职务／学科负责人及多义文化词：呈现原文与语境供核对，不用统一译名掩盖词义差异。
5. 规则限定第二章时，第一章同词不得误用该规则；重复原文在两个说话人或时间范围下可保存不同译法。
6. 前章批准译名或摘要改变后，旧引用和勘校显示变化，旧报告不能当当前；保留历史快照，不自动改后章正文或自动重跑模型。
7. 译文修改后原“已解决”需复核；合理例外只对指定位置及版本生效，不能把真实错译永久静音。
8. 草稿未完成、两窗口冲突、保存响应丢失后重试、重启恢复、viewer 写入拒绝与提交失败均检查实际持久内容；不能重复批准或把半章导出成新定稿。
9. 非默认章序、章内后半段揭示、倒叙、不可靠叙述分别检查，不把文件名排序或简单章号作为故事真相。
10. 纯人工路径无模型请求、无虚构 usage；AI 路径实际外发材料只含批准且适用的人物／术语及明确选择的参考，超预算明确拒绝而非静默截断。

工程验收使用公开应用层接口、本地请求捕获及各批具体提交的原生 CI；不把历史六项通过冒充新功能验收。界面批次需实渲截图与键盘／真实指针操作记录。文档批次只做链接和差异检查，不为规划触发付费模型。

文学验收另行获得材料与预算授权：以相同材料、模型、预算和审校覆盖，对比现有流程与新增工作台；人工译者交叉使用两种流程并平衡顺序，最终译文匿名交给双语评阅者。预先登记严重错译／漏译、人物称谓与口吻、跨章一致性、人修分钟数、残留问题及实际用量／费用的通过／停止标准。不得要求正在操作界面的译者“不知道用了哪种界面”，也不以模型互评替代盲评。

## 6. 本轮暂缓

不做全自动人物识别／知识图谱、全书自动替换、自动接受审校或定稿、未经选择外发笔记、远程嵌入、自动抓书／出版、多人实时协作。TMX、EPUB／DOCX、句级 SRX 及 XLIFF 在小说编辑闭环完成后按真实需求另排，不作为第一批前置条件。没有工程和文学对照之前，不承诺省时比例或出版质量。
