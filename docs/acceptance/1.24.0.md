# 1.24.0 验收记录

本版聚焦「打回再改一轮」的一键修订闭环：工部代码诏令完成后，若皇帝驳回改动、逐段 `--skip` 跳过部分段，或都察院复核提出逐段驳回意见，可直接以 CLI、Web 或 TUI 携带上轮上下文一键下发新一轮工部修订诏令，继续严格遵守暂存与逐段准奏原则。

## 验收项

1. **应用层修订草案与零新增事件（`crates/ziyuan-app/src/revise.rs`）**
   - `can_revise_task` 仅放行已完成、非译书、带写权限或改动的工部诏令；只读条陈、未完成诏令与译书任务均拒绝。
   - `draft_revision` 继承原诏令有效范围（盘上已删除路径自动收拢到最近已存在父目录）、沿用 `run_tests` 设定并汇总上轮 `--skip` 段号与都察院 `HunkVerdict::Reject` 段号。
   - `revision_edict_text` 组装原诏令、上轮改动状态与截断 diff、都察院复核与重点逐段意见、皇帝上轮评定、本次修订指示以及「先核对当前磁盘状态再呈报」提醒。
   - `Session::issue_revision` 校验自定义 `--scope`（拒绝 `..`、禁区与不存在路径），保留 `WriteFile` 与原 MCP 授权，通过现有 `Session::issue` 仅写入一条 `EdictIssued`，**不新增朝廷事件类型**，不抬高旧事件簿读取门槛。
2. **CLI 入口与补全（`crates/ziyuan-cli`）**
   - 新增 `ziyuan edict --revise <诏令ID> [--scope <路径>]... [--no-tests] [--queue] [--note <修订指示>] [修订指示]`。
   - 拒绝与 `--from-plan`、`--plan`、`--template`、`--dept`、`--tools`、`--mcp` 混用；`--note` 仅可配合 `--revise`；同步更新帮助文本与 bash / zsh / fish 补全。
3. **奉天门 Web 与紫禁城 TUI 闭环（`crates/ziyuan-web` / `crates/ziyuan-tui`）**
   - Web `/api/state` 为可修订诏令附带 `revise_draft`；新增 `POST /api/tasks/{id}/revise`（观政只读令牌返回 403）；前端奉天殿渲染「打回再改一轮（下发工部修订）」面板（遇改动已驳回、有驳回段、都察院弹劾或皇帝驳回时自动展开）。
   - TUI 诏令页新增 `V` 快捷键打开预填范围与工具的修订弹窗并下发工部修订诏令。
4. **自动化验证**
   - `cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets --locked -- -D warnings`、`cargo check --workspace --all-targets --all-features --locked`。
   - `cargo test --workspace --locked`（含 `revise_edict_carries_diff_censure_review_and_note_and_preserves_seal`、`edict_revise_flags_validate_cleanly`、Web `/tasks/2/revise` 权限与端到端测试、TUI `V` 快捷键测试）。
   - `node --test crates/ziyuan-web/src/*.test.mjs` 与 `python scripts/check-doc-links.py` 全部通过。
