# 1.3.0 译文记忆验收

验收日期：2026-10-31。已完成源码、本地构建与跨平台 CI 检查，新 crate 也已首次发布，维护者已确认自动发布配置。**完整应用的四平台正式下载包仍待本次发布工作流验收**，见[发布准备](../releasing.md#13-发布阻塞)。1.2.3 已独立发布，原有标签与资产不变。

## 交付范围

- 从当前有效的御览定稿收录原文与译文对，保留项目、章、块、段及定稿出处。未定稿、退回、资料变更、磁盘手改、结构不合格均不能成为参考。
- CLI 提供 `text memory status|build|search`；默认一个项目，跨项目须逐个 `--project`。Web 提供当前项目的状态、手动重建和查询，观政用户不能重建。
- 默认关闭；显式 `ZIYUAN_MEMORY_PROVIDER=local` 才计算。只有本地字符比较，没有远程嵌入服务，不理解文意，不承诺文学质量提升。提供独立的 `reference_prompt` 参考文本导出，结果不自动采纳，也不自动注入翻译提示。
- 缓存可重建，不增加事件类型、不改原文或定稿记录。建库替换工作区整份缓存，不是追加项目。损坏时明确拒绝，重建后恢复。

## 可核对的行为

### 命令行实跑

使用两个日文项目和一个未定稿英文项目，内容为本次原创短句及固定译文。通过公开应用接口准备暂存、准奏、定稿记录，之后使用实际 CLI；**没有调用翻译模型，不是文学质量测试**。

1. 未启用提供方时搜索退出 1，提示 `ZIYUAN_MEMORY_PROVIDER`，没有伪装成空结果。
2. 两个日文项目共收录 4 段。默认查询只回当前项目的 3 段；明确增加第二项目后才回 4 段。
3. 当前项目退回重修后，同一份旧缓存搜索只剩另一个已授权项目的 1 段。
4. 写入坏缓存后搜索拒绝，重新建库恢复为 1 段。建库与查询前后事件簿逐字节一致。
5. 用最终 release 构建搜索恢复后的项目，JSON 含 1 条有效参考及 `reference_prompt`；出处、定稿标识、外来文书边界与权限说明均保留，事件簿未变。

第一次退回命令漏写 `--reason`，按帮助改正后重跑；不把用法错误当成产品错误。

### 自动回归对应

- 定稿与失效：app 集成测试 `finalized_pairs_build_search_and_reopened_invalidation`、`applied_unstarted_and_manual_edits_are_not_eligible`、`changed_approved_context_invalidates_finalized_cache`。
- 文件与历史变动：`manual_edit_during_embedding_aborts_without_replacing_cache`、`manual_edit_during_query_never_returns_the_old_reference`、`unterminated_history_bytes_are_not_an_unchanged_watermark`、`snapshot_backed_session_rejects_rewritten_history_before_its_first_history_read`。
- 范围先于计算：memory 的 `scope_is_applied_before_embedding_ranking_and_limit`；app 的 `explicit_cross_project_scope_still_excludes_other_languages`。
- 损坏、锁与路径：`corrupt_cache_errors_and_lossless_rebuild`、`workspace_lock_spans_embedding_without_generation_changes`、`symlink_cache_directory_is_rejected_for_read_and_build`、`non_utf8_workspace_is_not_given_a_lossy_identity`。
- CLI：`memory_cli_is_explicit_and_rebuilds_only_derived_data`；Web：`memory_api_local_and_disabled`（分别以独立子进程检查默认关闭与 local）。
- 参考文本导出：`reference_export_keeps_instructions_inside_quoted_untrusted_material`，检验伪造边界与恶意指令作为引用保存、出处保留、没有额外权限或事件变动，空命中不产生参考文本。

### 浏览器实跑

Chromium 桌面 1280 像素与窄屏 390 CSS 像素，均为 2× 截图；天青、墨分、青绿共六个布局检查。三种窄屏的页面宽度均为 390，记忆区域宽 316，无横向越界。长出处正常换行，输入框与按钮完整可见。

- 实际点击重建、输入原文、搜索，出现 3 条当前项目参考，没有另一个项目的译文。
- 切换到未定稿英文项目，清除日文结果；建库为 0，查询显示没有有效定稿参考。
- 损坏缓存后显示通俗错误且重建入口仍可用，点击重建恢复。未启用服务的搜索与建库控件禁用。

## GitHub CI 跟进

[首轮 CI 41220825018](https://github.com/YuuUehara/Ziyuan/actions/runs/41220825018) 对应 [源码提交 7f55724](https://github.com/YuuUehara/Ziyuan/commit/7f55724ebf5c103987409894a61b503185e58531)：Linux 整套检查、Windows 功能、Rust 1.89、审计、Ubuntu 22.04 的 glibc 2.35 基线及离线包检查均通过，macOS 未通过。

macOS 唯一外层失败为 `non_utf8_workspace_is_not_given_a_lossy_identity`：`fs::rename` 创建非法编码目录时就返回 `Illegal byte sequence`（系统错误 92），还没有调用记忆库。其余 15 项 app 记忆测试通过；故意失败的临时文件探针子进程并非本轮失败原因。

修正仅在该用例中识别 macOS 提前拒绝非法编码的情况：必须准确是 EILSEQ（92）、原目录仍在、没有生成记忆缓存；其他准备错误仍然失败。如果系统允许创建该目录，则继续执行原有应用层 UTF-8 拒绝与无缓存检查，不跳过安全断言。Linux 保留原检查。产品代码、界面与截图均未改变。

[第二轮 CI 41221355883](https://github.com/YuuUehara/Ziyuan/actions/runs/41221355883) 对应 [macOS 用例修正 5a7ff38](https://github.com/YuuUehara/Ziyuan/commit/5a7ff38eb94930787efb120d168fcfa0084a676b)：macOS 和其他四项检查通过，Windows 失败在已有的 `approval_retries_until_the_other_process_finishes`，不是译文记忆测试。该测试及其生产代码与当时的 `origin/main` 相同，首轮 Windows 也曾通过。

Windows 日志显示一次「恢复记录已完成但未收尾」的正常拒绝，被测试里的第二次状态读取误判为不可重试：对方在这之间已完成收尾。修正仅涉及测试的重试判据，依据原始错误中明确的「写入前拒绝」前缀与「未收尾」原因决定，不让更新的状态推翻已经发生的拒绝；其他错误仍立即失败，100 次／2 秒的等待上限不变。Linux 上恢复重试与双任务并发准奏各重复 50 次均通过，最终文件、记录清除、无暂存残留等断言保留。没有改变生产规则或界面。

[第三轮 CI 41222331265](https://github.com/YuuUehara/Ziyuan/actions/runs/41222331265) 对应 [重试修正 2307d4d](https://github.com/YuuUehara/Ziyuan/commit/2307d4dad63bf41490cc480298d999b874c30871)：全部六项通过，包括 Windows、macOS、Linux 全套检查、glibc 2.35 基线、Rust 1.89 和依赖审计。两处失败均已取得原生平台复验结果。

最终本地检查另遇一次 `sweep_refuses_a_directory_with_an_unreadable_lease`：预览通过后，实际清理报告 `LeaseBusy`。当时该测试及探针与 `origin/main` 相同，但主分支整组探针连续 100 轮未重现，**未以旧问题为由豁免**。测试探针现在在预览结束时明确解锁，之后才关闭句柄；34 项探针测试连续 50 轮通过。独立复制句柄对照确认仅关闭一个句柄可继续持锁、明确解锁则释放；原始失败现场未捕获复制句柄，不能把该机制说成已经证实的现场原因。生产清理代码与断言不变，仍须最终完整检查及本次提交的跨平台 CI。

`cargo publish --dry-run --locked -p ziyuan-memory` 验证后，实际执行 `cargo publish --locked -p ziyuan-memory`，输出 `Published ziyuan-memory v1.3.0`。注册表确认发布者为 `YuuUehara`，许可证为 `MIT OR Apache-2.0`，版本未撤下；下载包 SHA-256 与注册表一致，包内九份源码／原始清单文件与提交 `2307d4d` 逐字节一致，版本出处也指向该干净提交。
