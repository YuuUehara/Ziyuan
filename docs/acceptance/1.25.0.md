# 1.25.0 验收记录

本版为只读探索与工部改代码补齐「版本库上下文」三件只读工具：`vcs_status`、`vcs_diff` 与 `vcs_log`。模型无需任意 shell 权限即可了解未提交变动、近期提交与具体 diff，同时严守玉玺范围、禁区过滤与外来文书边界。

## 验收项

1. **三件只读版本库工具（`crates/ziyuan-runtime/src/tools/vcs.rs`）**
   - 随 `Capability::ReadFile` 一并授予，**不新增玉玺代码、不新增朝廷事件**。
   - 自动检测并优先使用 Jujutsu（`jj`），否则回退 Git（`git`）；非版本库目录返回清晰中文报错。
   - `vcs_status`：可选 `path`，仅返回玉玺范围内且非禁区的未提交改动，范围外与禁区条数仅以匿名计数提示。
   - `vcs_diff`：可选 `path`、`rev`、`staged`（仅 git）、`stat_only`；对输出按 `diff --git` 区段二次按路径过滤，单次输出严格截断至 32 KiB（UTF-8 字符边界安全）。
   - `vcs_log`：可选 `path`、`rev`、`limit`（1–30，默认 10），输出近期提交摘要。
2. **安全与防注入边界**
   - 严禁任意参数或 shell：`validate_rev` 拒绝空串、超长、以 `-` 开头的选项注入、含 `:` 的路径偷渡（如 `HEAD:.env`）与非安全字符。
   - 子进程 `env_clear()` 后仅继承 `TEST_ENV` 无害子集（不传 API Key / GitHub Token），禁用交互提示与 pager，设置 15 秒超时。
   - 无论 `path` 是否指定，`.ziyuan`、`.git`、`.jj` 与 `.env*` 均被拒绝且从状态与 diff 输出中二次剔除；全部输出照常经 `agent_loop` 的外来文书暗号边界包裹与提示注入扫描。
3. **自动化验证**
   - `cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets --locked -- -D warnings`、`cargo check --workspace --all-targets --all-features --locked`。
   - `cargo test --workspace --locked`（含 `validate_rev_rejects_option_injection_and_colon_path_smuggling`、`git_vcs_tools_enforce_scope_filter_secrets_and_support_diff_and_log`、`vcs_tools_fail_cleanly_outside_any_repo` 与 `reference_execution` 工具集核验）。
   - `node --test crates/ziyuan-web/src/*.test.mjs` 与 `python scripts/check-doc-links.py` 全部通过。
