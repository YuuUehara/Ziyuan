# 1.26.0 验收记录

本版增强工部验证闭环：在不开放任意 shell 的前提下，允许皇帝通过 `ZIYUAN_TEST_COMMANDS` 预设多个命名检查／测试命令（如快速 `check`、`clippy` 与全量 `test`），并为 `rustc`/`cargo`、`tsc`、`mypy`/`pyright` 补充结构化编译诊断摘录，同时测试副本跳过 Python 常见缓存目录。

## 验收项

1. **命名检查／测试命令白名单（`ZIYUAN_TEST_COMMANDS`）**
   - `ziyuan_runtime::tools::parse_test_presets` 解析分号或换行分隔的 `名称=命令`，限制名称为 1–32 位 ASCII `[A-Za-z0-9_-]`，拒绝重复名、空命令与非法格式。
   - `run_tests` 新增可选参数 `preset`：不传时沿用 `ZIYUAN_TEST_COMMAND`（未设则取 `default` 或首个预设）；传入时仅允许命中皇帝白名单中的预设名，未知预设直接拒绝并列出允许名单。模型绝不能改写或拼接命令。
   - `ziyuan-cli` 启动后端时严格校验 `ZIYUAN_TEST_COMMANDS`，并更新帮助与环境变量契约测试。
2. **结构化编译／类型诊断摘录（`crates/ziyuan-runtime/src/tools/failures.rs`）**
   - 当 `run_tests` 失败且非已知单元测试框架输出时，自动识别 `rustc`/`cargo`（须带 `--> 文件:行:列` 定位，忽略末尾 `could not compile` 汇总）、`tsc`（括号与冒号两种格式）及 `mypy`/`pyright` 诊断，输出 `〔编译诊断〕`（上限 8 条）。
   - 测试成败仍严格以退出码为准，都察院核验语义不变。
3. **测试副本轻量化**
   - `SKIPPED_DIRS` 在 `target`、`node_modules` 之外跳过 `__pycache__`、`.pytest_cache`、`.mypy_cache`、`.ruff_cache`，减少搜索与测试副本复制开销。
4. **自动化验证**
   - `cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets --locked -- -D warnings`、`cargo check --workspace --all-targets --all-features --locked`。
   - `cargo test --workspace --locked`（含 `compiler_diagnostics_extract_rustc_tsc_and_mypy`、`test_presets_parse_and_enforce_strict_allowlist` 与 `contract` 环境变量清单测试）。
   - `node --test crates/ziyuan-web/src/*.test.mjs` 与 `python scripts/check-doc-links.py` 全部通过。
