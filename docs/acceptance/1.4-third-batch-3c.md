## 实现和统计口径

- 只读 `ziyuan text usage <项目ID> [--json]`：先校验真实项目与源文副本，读取朝廷一致快照及全部历史，按初译、忠实审校、文风审校、修订列出所有关联任务，含失败、撤销、旧稿、重复修订和中断后的再次指派。没有朝廷时明确拒绝，不自动初始化。首版 CLI 先行，不新增 Web 表单。
- 执行 `ModelUsage` 根据此前最近的 `TaskAssigned` 归属模型，不把全部旧用量套到任务最新模型。票拟、分办、廷议、复核、复勘直接读取每条事件／发言的用量与模型，不使用仅保留最新模型的汇总字段倒推历史费用。
- `recorded_usage` 是已报告的小计；完全未报告时 JSON 为 `null`、人类输出为“未知”。服务端明确报告零 token 与未报告不同。即使任务有 usage 事件，也可能有其他调用未报告，因此不能宣称完整覆盖。治理事件的零还可能表示手动操作或缺 usage，不冒充已知零费用调用。
- `usage_events` 仅为执行用量事件数，不是 HTTP 请求数。同一 trace 的多条用量仍分别记账；重试可共用 trace。任务数、指派尝试数、工具审计次数及失败数各自展示，不互相替代。完整 HTTP 次数及历史精确耗时未知；分钟级时辰不是精确计时。
- 每条记账项保留用途、模型、tokens、费率来源和估价；按币种分别汇总。无模型／费率的用量独立列为未定价，不能当免费。费率是**本次查询读取**，不是执行时锁价。内置 DeepSeek 2026-10 高峰未命中缓存价未实时核价；环境价注明 `ZIYUAN_LLM_PRICE`。非有限或负费率拒绝估价。缓存折扣、服务商账单、订阅实际计费均未据此核实。
- `usage_reconciled` 只表示已记录小计与朝廷累计相符，不证明服务端 usage 完整或计费正确。本件预算不是全局／官员余额，不意味着还有权继续调用；现有余额预检、输出限额及停止策略未改。

实际用法及 JSON 字段见[文本工具](../text-projects.md#逐阶段用量账本与请求材料精简)。

## 精简的保留条件

只处理本轮真实执行成功的 `read_file`：参数字符串、完整返回字节均相同，才把较早返回改为指向最新完整返回的明确短说明，且说明必须更短。不同参数、变化后的重读、错误、搜索／写入等其他工具返回不压缩；每个工具调用与返回的配对、工具执行和审计不变。

精简只是**请求投影**：原始对话历史保留全文，每次在现有 `abridge` 后重新生成投影，排除被节略的材料，不存会随着目标老化而悬空的指针。指针仍置于同一个外来材料安全边界中。该优化会克隆请求历史、比较合格读取，优化的是传输重复而非内存；不声称延迟或缓存收益。

没有省略当前源文、读音、批准上下文、选中参考、朱批和必要审校意见，不减少词义核对、朱批复核、双路审校或人工分批验收，也不自动启动下一块。其他工具输出及原有节略策略保持不变。
