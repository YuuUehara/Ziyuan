# 1.2.3 验收记录

本版只修复 1.2.2 的两处 CI 问题，不包含正在开发的 1.3 翻译记忆库。界面与实际清理规则不变，未重新拍摄界面截图。

## 失败原因与修复

[1.2.2 CI 41211184121](https://github.com/YuuUehara/Ziyuan/actions/runs/41211184121) 的 Linux 检查在 `temp_lease_probe.rs` 报多余的 `mut`；macOS 的 `temp_without_lease_and_foreign_leases_are_retained` 则把 `LeaseContentMismatch` 错当成必须为 `LeaseUnparsable`。两处问题都已在未修改的 Linux 代码上复现：Linux 的 CI 先被 clippy 挡住，并不是该平台没有第二处问题。

`C:temp` 在 Unix 是普通文件名，在 Windows 是带盘符的相对路径。因此研究探针在 Unix 必须按“内容不符”保留，在 Windows 必须按“无法解析”保留；实际清理器本来就在所有平台拒绝冒号，本次不改它。测试新增所有平台都应拒绝的 `../temp`，并确认原文件与所有租约内容未变。

## 本地已通过

Linux orb 上运行以下命令，退出码均为 0：

- `cargo check --workspace --all-targets --offline`。
- `cargo fmt --all -- --check`。
- `cargo clippy --workspace --all-targets --locked -- -D warnings`。
- `bash scripts/smoke.sh`：先跑全工作区测试，再跑 CLI 流程，最后输出 `ZiYuan smoke test PASS`；真实 git-delta 用例通过，未因缺少 delta 而跳过。
- `cargo +1.89.0 check --workspace --all-targets --locked`。
- `cargo audit`：没有已知漏洞；间接依赖 `bincode 1.3.3` 仍有 `RUSTSEC-2025-0141` 停止维护警告，不将警告说成已修复。
- `bash scripts/check-package.sh target/debug/ziyuan 1.2.3`：离线运行、版本与上下文配置检查通过。这是本地二进制检查，不是官方下载包验收。

Linux 本地用例按 `cargo test --workspace --locked -- --list` 枚举，共 507 项，其中 34 项为研究探针；不叠加子进程日志中的汇总数字。平台限定用例使这个数字不必与 Windows 相同。探针有一项故意让子进程以未知参数失败，父用例核对拒绝后通过；不把这段预期日志当成整个套件失败，也不忽略其他真实失败。

发版前运行全工作区测试、CLI smoke、fmt、严格 clippy 和 Rust 1.89 检查，并等待同一提交的 Linux、macOS、Windows CI 通过。推送标签后，发布流程在四个平台重新下载并运行刚上传的程序包，全部通过才公开 Release；随后按现有流程发布 crates.io。最终结果与日志链接补在本版 Release 说明，不以计划代替成功记录。
