## 1. 实测依据与结论边界

历史实测基线为第二批提交 [ca4db380](https://github.com/YuuUehara/Ziyuan/commit/ca4db380ce58b884cbde00861be14173075dcbb9)，[六项跨平台 CI 全部通过](https://github.com/YuuUehara/Ziyuan/actions/runs/41282897132)；实测当时尚未发布为 1.4，不是当前版本状态。

《坊っちゃん》前两章实测：13,480 个去空白、去读音的源文字符（含标点），35 段、487 对 ruby、5 个块；原始派生正文含空白为 13,482 字符。DeepSeek `deepseek-flash` 完成 5 次初译、10 次只读审校和 6 次修订，共 21 个任务，不等于 21 次 HTTP 请求。各批读稿、核词、写朱批、检查修订后再启动下一批。

本轮输入 2,111,450、输出 282,259，合计 **2,393,709 tokens**；按程序内置费率估算 **6.480972 元**，不是供应商实际账单，也不含执行者与外部核对成本。四种 TXT／MD 导出和原件字节核验通过。一次工具失败后任务继续完成，持久日志没有具体错误文本，不能断言根因。没有测试强制中断恢复或本轮 Web 流程。

原始证据保存在本线程 `.amp/in/artifacts/1.4-novel-10k/`：`report.md`、`paragraph-comparisons.md/json`、`lexical-notes.md`、`usage.csv`、`metrics.json`、`export-proof.json` 和 `verify.py`。它们不是仓库内长期测试依赖；实施时从中提取最小、自包含且有权使用的回归样本，不能依赖 `/tmp` 项目或忽略目录才能运行 CI。

关键发现：

| 实测现象 | 产品需求 | 不可推导的结论 |
| --- | --- | --- |
| 狸变狐狸、教头与数学主任混淆 | 带来源的跨块参考及称谓核对 | 字符串匹配能判断物种、职务或所有同义表达 |
| 主语、施受、否定、五倍关系错误 | 逐段勘校清单与修订后确认 | 段落结构 valid 就是语义正确 |
| 两路同模型审校遗漏错误，还给出错误建议 | 每项意见可接受、驳回或存疑，须有依据 | 双审等于独立专家背书 |
| “甥”、毛繻子等须查词，词典解释又可能破坏笑点 | 词证与适用语境分开，支持暂定／不确定 | 词条定义可机械替换正文 |
| 重复材料、多轮工具交互带来较大用量 | 按阶段对账并测量可消除的重复 | 已证明某一环节是主要成本根因 |

“氷水”初译已按刨冰词证处理，不列作纠错收益；残余译腔与暂定译名仍需文学审阅。本次是 AI 执行与核对，不称双语专家人工终审，也不证明出版质量。

## 2. 范围与优先级

### 3A / P0：把人工选中的参考真正交给一次任务

**用户结果：** 查询有效定稿后，选择具体段落，看到将发送的全文与出处，再为目标块初译或修订下诏；任务记录可回查当时用了什么。不选参考的旧流程保持不变。

- 复用 `memory.rs` 的资格核对、候选与 `reference_prompt`，以及 `translation/status.rs` 的有效定稿判断，不再造资格系统。相似度仅为匹配分数，不是可信度。
- 按项目／章／块／段、来源定稿和内容摘要绑定选择；快照绑定本次目标与操作。CLI 跨项目逐个授权，Web 首版限当前项目，viewer 不得下诏。默认不选、不自动召回或晋升术语。
- 下诏前和执行前重查来源与权限；任一项失效整次停止，不偷偷删项、换项或转无参考。来源退回后即便同文重定稿，旧确认也不可沿用。
- 预览明确外发给当前模型的原译文与出处。参考只是资料，不能覆盖原文、批准术语或朱批，不扩大工具权限；只读审校首版不消费这份选中参考。
- 固化任务快照、提交身份及恢复规则。相同提交身份与内容返回原任务，不同内容拒绝；事件扩展先做旧日志兼容设计，不把事实仅放进可重建索引。
- 3A 已固定上限：最多 8 条，完整额外参考材料不超过 8192 UTF-8 字节，持久化任务快照不超过 32768 字节。计入边界与出处，不截断；不是完整模型对话，也不是精确 token／模型窗口上限。
- 执行后来源变化时，保留“当时已发送”的事实并标示现已失效；**首版不新增来源引用变化自动阻止定稿的依赖门控**，不能暗示已经提供该保证。

### 3B / P1：词证与逐段勘校

**用户结果：** 看见可能冲突的译法和对应原段，记录为什么改／不改，再检查修订是否解决问题；未解决项不会消失在“任务完成”里。

总标题采用“逐段勘校”，面板／功能标题采用“词证与逐段勘校”。六事逐项勘校，记录所据与存疑。此为人工核对记录，不代准奏，亦非御览定稿。

- 当前实现复用批准词表已有的 `allowed`、`scope`、`note`、上下文版本与朱批，不并建自动术语库或禁用译法字段。源段命中词条而译文没有任一 `allowed` 时提供字面提示；`scope` 为自由文本，适用性仍由人核对。人名、物种、职务、金额的上下文判断不承诺自动识别。
- 词证最小记录包括原文短引、来源 URL／书目信息、定位、核对说明、适用语境、暂定或确认状态及关联段落。只存链接不自动联网；未主动选用的笔记不自动外发。模型提案仍须人工选择与批准才能进入现有上下文草稿，不修改已批准快照。
- 勘校六事采用：言行归属、事理正反、数目分寸、前后次第、称谓名分、谐趣留白；直白说明、短例及不变的内部 JSON 键见[指南六事表](text-projects.md#逐段勘校六事意见处理与问题状态分开记录)。每项的意见处理可记接受、驳回、待查或不适用，问题状态另行记录；接受意见不等于问题已解决。关联审校意见、词证、朱批和实际修订差异。
- 清单绑定源文、现行译稿、上下文与朱批的摘要及来源任务；材料变化即标旧记录需复核。模型回奏只作建议，不能填成人工已验收；没有录入记录也不能显示已检查。
- 首版是**辅助记录与提示，不增加强制定稿门槛**，也不改变旧 `text check` 的结构语义或旧项目定稿资格。界面分开显示结构通过、意见已处理、人工复核及有效定稿四种事实；“人工复核”状态不随功能标题改名，不等于专家终审。
- 沿用批次人工控制：本块核对后再启动下一块；有争议可停下，不增加无人值守批量翻译。批准上下文的新版本沿用现有失效规则，不能为保住试验状态原地修 v1。

### 3C / P2：可解释用量与有对照的优化

当前源码以只读 `text usage <项目ID> [--json]` 交付四阶段账本，不新增 Web 表单或事件格式。缺失 usage 保持未知，按事件当时模型、查询时费率分别估价；完整 HTTP 次数、历史精确耗时和账单不从现有事件虚构。已完成固定脚本本地 HTTP 对照，仅精简逐字节相同的重复成功读取，详见[3C 工程证据与局限](acceptance/1.4-third-batch-3c.md)。没有新增付费文学对照。

- 基于现有 usage／budget 汇总初译、忠实审校、文风审校、修订的输入／输出、任务状态和估算费用；缺失 usage 标未知，不填零。区分任务数、请求数与工具调用数，只报告已有证据能支持的指标。
- 把费率来源、估算与账单、缓存折扣是否已核对分开；预算不足时明确停止，不减少审校次数或跳过朱批来换低费用。
- 先用本地捕获服务测量重复材料与请求大小，再选择最小优化。只去掉可证明冗余的内容，不省略当前原文、读音、批准上下文、选中参考、朱批或必要的审校意见。
- 付费对照另行授权：运行前登记同一模型、样本、配置、审校覆盖、token／人民币估算预算及停止条件；不能把此前万字试验授权当作持续调用许可。先同一样本小批配对，不直接再跑整部小说。
- 报告逐阶段用量、耗时、严重错译／残留、操作者修改量及局限；AI 核对时间不冒充专家人工分钟数。没有对照不宣称节省比例或文学收益。

## 3. 实施顺序与代码边界

| 阶段 | 主要所有权 | 交付与进入下一阶段条件 |
| --- | --- | --- |
| 设计冻结 | `translation/`、任务持久化／事件编码边界 | 先定选择快照、失效、去重和兼容；检查现有公开接口可否直接扩展，不预造通用框架 |
| 3A 应用层 | `memory.rs`、`translation/session.rs`、`translation/export.rs` 及任务执行前核对 | 本地捕获服务证实只发送选中资料，失效时零请求；无参考旧测试不变 |
| 3A 前端 | `ziyuan-cli/src/text_commands.rs`、`ziyuan-web/src/text.rs`／`index.html` | 先 CLI 后 Web，共用应用层权限与事实；说明选择、入队、发送、批准区别 |
| 3B 复核闭环 | `translation/context.rs`／`zhupi.rs` 与现有状态、审阅入口 | 先定证据记录的持久化和版本，再接提示与清单；变更后旧记录不会冒充当前复核 |
| 3C 量化优化 | 现有 usage／budget 所属模块及材料组装 | 先保存基线与本地测量，再做最小优化；付费复验单独获准 |
| 收尾（历史条件） | 指南、CHANGELOG、验收记录 | 本地检查及具体提交的跨平台 CI 通过后独立执行 1.4 release；当前下载包与 publish 已成功，crates 仍待结果 |

分阶段提交和验收，不把三个阶段写成不可回退的大改；实际模块拆分、命令名、JSON 字段及事件代码在实施设计中确定，本计划不将它们提前冻结为公开接口。

## 4. 验收清单

### 工程必过：离线、确定性、可回归

1. 三条候选只选中间一条，捕获实际执行请求验证不含其余两条；空选择仍走旧流程。已发送快照和任务记录对应。
2. 搜索后／下诏后分别退回、重定稿、手改、删除或改变授权；执行前失效零模型请求、原稿不变。仅结果排名变动或索引重建不偷换选择。
3. 未授权项目、不同语言、伪造来源、viewer 写操作拒绝；跨项目授权不由索引建库范围自动继承。
4. 数量与编码字节上限的两侧均测，使用日文、长出处和引用边界；超限不排队、不截断。参考含恶意指令也不获得写权限。
5. 并发提交、响应丢失、进程重启后重试，同一身份仅一个任务；同身份不同内容拒绝。旧事件／旧项目照常读写；来源执行后失效仍可追查发送时快照。
6. 复核记录绑定的材料变化后显示需复核；驳回意见、存疑和不适用均保留，不由模型“已修正”自动勾通过。旧结构检查及定稿规则不变。
7. 从实测抽取最小语义案例：纸钞换银币的方向、“她不必疼我”的主体、总数五倍与增加五倍、狸与狐狸、副校长与数学主任、词典解释破坏笑点。**这些验收记录与对照展示能力，不断言规则能自动翻译正确**；预期由人工阅读原文独立给出。
8. 用量账本含失败、追加修订、缺失 usage；分阶段和总计对账，不重复计任务。优化前后捕获请求保留全部必要资料，不能仅比较最终译文字数。
9. Web 三主题、1280 桌面和 390 CSS 像素窄屏实跑选择、长出处、警告、加载、失败、失效及 viewer；输入框、选择文件按钮和既有按钮保持设计统一、边框内换行与对齐。检查截图及真实指针／键盘录屏、旧异步响应和刷新保留状态。

### 文学效果：独立门槛

工程检查之后才进行获准的小样对照，保持词义核对、朱批复核和分批验收。不用结构 valid、模型互评或自动提示命中率替代双语评估；没有专家审阅就如实标注。暂定译名、译腔、笑点和读者注释单独列残留，不能用测试项目 Finalized 状态称出版完成。

## 5. 不在第三批范围

不自动晋升词表、自动接受审校、自动准奏／定稿，不新增远程嵌入或词典抓取，不接 Kakuyomu 登录／正文订阅，不追加／替换旧章，不做 EPUB、出版或专家质量保证。工具失败错误详情的持久化与强制中断恢复需独立诊断、设计；不能因一次 `list_files` 失败就改产品，或宣称本次已经覆盖恢复。

第三批已完成，1.4.0 已按独立流程推进发布，最终版本 CI 与实际下载包检查见页首汇总；未修改 1.3.0 资产。当前只待发版收尾和文档统一，随后盘点代码任务闭环，不创建下一批计划。完成第三批不自动授权新付费长跑；新增付费对照仍需先登记预算并另行授权，不能将工程通过称为小说译文质量通过。
